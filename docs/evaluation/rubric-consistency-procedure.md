# 评分一致性人工抽检规程

本规程把 S3 核心内容展示第 11 页的承诺「评分一致性由人工抽检复核，抽检结果与量表版本一起留档」
落成固定动作：抽样比例、复评口径、人工复核清单、偏差处置与留档命名都在这里冻结，
抽检脚本 backend/scripts/audit_rubric_consistency.py 是执行入口。

适用量表：interview-rubric-v1（当前值）及后续新增的 rubric_version。量表版本变化即口径变化，
抽检只比较同一 rubric_version 的报告。

## 一、抽样

### 1.1 抽样总体

抽样总体 = 数据库里已结束（status=completed）、已产出报告、且至少有一条作答记录的真实场次。
没有作答或没有报告的场次不能复评，脚本会记入留档的 skipped 列表并说明原因。
量表版本与抽检量表不一致的场次排除在总体之外，不参与同一轮比较。

### 1.2 分层与随机

- 分层维度：rubric_version × role（岗位）。同一层内的报告口径一致，才能放在一起比较。
- 层内按 created_at、session_id 稳定排序，再用固定 seed 随机抽取，保证同一批输入与同一 seed
  的结果完全可复现。默认 seed 为 20261009，可用 --seed 覆盖并把实际值写进留档。
- 层间名额按总体占比用最大余数法分配；层内样本不足时把余量让给其他层，不会超过各层总体。

### 1.3 比例与样本量

- 当期总体不超过 30 份：全抽（--sample-ratio 1.0，默认值）。样本少时全抽比抽一部分更能说明问题。
- 当期总体超过 30 份：默认抽样比例 20%，且每个分层至少 1 份、整轮样本量不少于 5 份。
- 需要精确控制样本量时用 --sample-size N 覆盖比例，N 为样本量上限。
- 实际抽样比例、seed、总体与样本量必须随结果一起留档（脚本自动写入）。

抽样与复评命令示例（在 backend 目录下执行）：

    .venv/bin/python -m scripts.audit_rubric_consistency --dry-run
    .venv/bin/python -m scripts.audit_rubric_consistency --sample-ratio 1.0
    .venv/bin/python -m scripts.audit_rubric_consistency --sample-size 5

--dry-run 只打印抽样计划，不调用模型也不落盘，用于先确认总体与分层是否符合预期。

## 二、复评口径

脚本对每个抽中样本，用 interview 模块当前使用的同一份评分 prompt（_REPORT_SYSTEM）、
同一份提问拼装（_report_user_prompt）、同一套分数与证据收敛（_coerce_scores）重新跑一遍评分，
通过 llm.chat_json 发起调用。它不新写评分标准，也不复制一份 prompt；量表版本与 prompt 指纹
（sha256）随留档存储，prompt 一旦变化就能从指纹看出口径漂移。

复评使用 temperature=0，与初次报告一致。留档记录 provider、model 与 endpoint host，
不记录 api key。

## 三、人工复核看什么

脚本负责机器可核对的部分，人工复核负责判断机器判不了的语义。抽检人逐样本核对以下五项，
核对结果逐行填进留档 .md 的「人工复核记录」表：

1. 证据是否为原话：每个维度的 evidence 必须能在候选人作答原文中找到。脚本已做逐字核对并丢弃
   非原话证据；人工至少每维抽查一条，确认没有被拼接、改写或张冠李戴。
2. 分数是否与证据一致：证据支持的表现档位与分数是否匹配，是否存在「证据强但给低分」「证据弱但给高分」。
3. 证据不足是否给 null：模型找不到原话证据时，该维度必须是 score=null 且 evidence=[]，
   不允许用 0 分或编造的分数顶替。
4. 四维是否齐全：correctness / depth / rigor / fit 四个维度各一条、不重复、不缺失。
5. 有无编造与串号：证据不得来自其他场次或其他候选人的回答。

## 四、判定与处置

### 4.1 判定规则（冻结）

对全部可比维度（原分与复评分都非 null 的维度）计算：

- 四维合并平均绝对偏差（所有可比维度差值的绝对值平均）
- 单点最大偏差（所有可比维度差值绝对值的最大值）
- 完全一致率（差值恰为 0 的比例）与 ±5 分内一致率（差值绝对值不超过 5 的比例）

判定：

- 通过：四维合并平均绝对偏差 ≤ 5 分，且单点最大偏差 ≤ 10 分，且可比维度覆盖率 ≥ 80%。
- 不通过：覆盖率达标但两个阈值有一项越界。
- 无法判定：可比维度覆盖率低于 80%（大量维度证据不足或复评失败，样本不足以支撑结论）。

### 4.2 阈值依据

- 评分是 0–100 的整数，四维用于导出「平均分」与「薄弱维度（低于 80）」两类对外结论。
- 平均绝对偏差上限取 5 分（满分的 5%）：平均意义上的漂移不超过半个等级档，不会把
  「是否薄弱」的结论整体推过边界。
- 单点最大偏差上限取 10 分（满分的 10%）：允许个别维度有真实抖动，但拒绝大偏移。
- 不把「完全一致」设为门槛：模型评分天然有浮动，强制 0 偏差会把正常采样噪声误判为失败；
  完全一致率与 ±5 分内一致率作为稳定性旁证一并报告。

### 4.3 处置

- 不通过：按维度定位越界样本。判断根因属于 prompt 歧义、证据口径还是模型波动；
  任何修改评分 prompt 或维度定义的动作都必须新增 rubric_version，不得原地改语义。
  处理动作与结论写入留档「处置」列，并在对应 issue 里留痕。
- 无法判定：补充抽样（缩小分层或直接全抽）后重跑；连续两轮仍无法判定时，把证据不足的
  维度定义问题升级为量表修订项。
- 边缘结果（平均绝对偏差 3–5 分或最大偏差 8–10 分）：判定为通过但记入观察项，
  下一轮抽检重点复核。
- 已知边界：复评与初评使用同一模型且 temperature=0，只能证明口径稳定，不能替代跨模型或人工盲评；
  单轮抽检只覆盖本轮抽中的场次，样本量不足时结论会标记为无法判定。

## 五、留档位置与命名

- 人可读：docs/evaluation/rubric-consistency-YYYY-MM-DD.md（抽样表、逐维偏差、逐样本对照、
  人工复核记录、判定依据、结论、复现命令）。
- 机器可读：docs/evaluation/rubric-consistency-YYYY-MM-DD.json（抽样参数、逐样本原分/复评分、
  逐维差值、复评证据原文、汇总与判定、输入指纹）。
- 同日重跑：脚本在未加 --force 时拒绝覆盖已有留档；输入（样本、量表、prompt、阈值、模型）未变时
  直接跳过、不重复调用模型。需要保留多轮结果时用 --force 覆盖前先另存，或用 --date 指定日期。
- 人工复核结果回填 .md 的表格与 .json 的 manual_review 字段，不需要重新调用模型。
- 留档不得写入绝对家目录路径；仓库隐私门禁会扫描已跟踪文件。

## 六、复现命令与测试

    cd backend
    .venv/bin/python -m scripts.audit_rubric_consistency --dry-run
    .venv/bin/python -m scripts.audit_rubric_consistency --sample-ratio 1.0
    .venv/bin/python -m pytest tests/test_rubric_consistency.py -q

## 七、执行角色与频率

- 抽检执行人：负责演示材料与评测结论的成员；每轮至少一人独立复核，复核人不能是本轮复评脚本的
  直接负责人（同人时在留档中注明）。
- 执行频率：量表版本变更后、重要演示或提交前、以及每月至少一次。
- 每轮结果必须同时更新 .md 与 .json，并把判定与处置反馈到对应 issue。
