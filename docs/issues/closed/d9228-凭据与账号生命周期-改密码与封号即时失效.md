# 凭据与账号生命周期：改密码与封号即时失效

## Background

仅有登录会话还不够：改密码与封号必须立即让已有会话失效，否则被撤销的凭据仍可继续访问。

## Scope

- `POST /auth/password`：校验当前密码，更新哈希，撤销该用户全部 Redis 会话并清 Cookie。
- `POST /auth/users/{user_id}/ban`：仅管理员；写入 `is_banned`/`banned_at`/`banned_reason`，撤销该用户全部会话；禁止封禁自己。
- 扩充机器错误码：`UNAUTHENTICATED`、`INVALID_CREDENTIALS`、`ACCOUNT_BANNED`、`FORBIDDEN`、`EMAIL_ALREADY_REGISTERED`。
- 测试：登出即时失效、改密码后旧会话 401 且旧密码不可登录、封号后目标会话 401 且登录被拒、非管理员封号 403。

## Non-goals

- 解封、封禁审计日志、通知与申诉流程。
- 会话列表、单设备撤销与滑动续期。

## Acceptance Criteria

- [x] `POST /auth/password` 校验当前密码，成功后该用户全部会话立即失效。
- [x] 改密码后旧密码登录失败、新密码可登录。
- [x] 封号仅管理员可执行；封禁后目标用户全部会话立即失效，登录返回 `ACCOUNT_BANNED`。
- [x] 管理员不能封禁自己。
- [x] `uv run --directory backend pytest` 与 `archkit inspect .` 通过。

## Implementation

- 改密码：`app/modules/auth/service.py` 的 `change_password` 校验当前密码与新旧差异，argon2 重哈希后调用 `session_store.revoke_all_sessions` 删除该用户全部会话；api 端点 `POST /auth/password` 返回 204 并清 Cookie。
- 封号：`ban_user` 校验不能封自己，写入 `is_banned`/`banned_at`/`banned_reason`，再删除目标用户全部会话；`POST /auth/users/{user_id}/ban` 经 `require_admin` 保护。
- 撤销实现：`auth:user_sessions:<user_id>` 集合索引记录该用户所有 token 哈希，`revoke_all_sessions` 逐个删除 `auth:session:<sha256>` 并删除索引；下一次请求因 Redis 无 key 返回 401。
- 错误码与异常：`UNAUTHENTICATED`/`INVALID_CREDENTIALS`/`ACCOUNT_BANNED`/`FORBIDDEN`/`EMAIL_ALREADY_REGISTERED` 及对应 `ApiException` 子类。
- 文档：`docs/design.md` 认证接口与撤销语义、`backend/README.md` 认证模块说明已同步。
