# 个人资料页支持直接编辑

## Background

/profile（SCR-004 个人资料）目前只能通过「对话维护资料」抽屉读写：基本信息与事实条目都要先经 AI 解析、再确认，才能落库。用户故事 US-7.1/US-7.2/US-7.6/US-7.9/US-7.10 要求用户可以直接建立与修正事实、集中维护基本信息，屏幕流定义 SCR-004 的 Primary Actions 也包含「新增和编辑事实」。缺少直接编辑路径时，改一个字段也要走一轮对话，成本与不确定性都不合理。

## Scope

- 基本信息卡新增「编辑」入口：姓名、一句话头衔、邮箱、电话、城市与链接可在页面内表单直接修改并保存。
- 每个事实分区新增「手动添加」入口，每条事实新增「编辑」入口；表单覆盖类型、标题、内容、标签、证据状态、可见性。
- 保存后立即更新页面：新增条目置顶并高亮，更新条目就地刷新。
- 保留既有对话入口：「对话维护资料」「对话编辑」「对话添加」「对话更新」全部不变，两条路径写同一份本地状态。
- 视觉复用对话卡片与结构化编辑器已有的表单语言（card-soft、border-input、focus:ring-ring/30、primary/border 按钮），不引入原型之外的新视觉规则。

## Non-goals

- 不实现删除事实（US-7.7 的引用影响确认单独处理），不做批量编辑与排序。
- 不接入 FastAPI，lib/api.ts 维持 mock；新增函数按真实 REST 端点命名并写清注释。
- 不改动 backend/、docs/prd 与 docs/user-stories。
- 本期不向 ui/prototypes/index.html 补充 Profile 直接编辑状态：该原型只覆盖首页；直接编辑沿用页面既有表单语言，不新增未记录的视觉规则。

## Acceptance Criteria

- [x] /profile 基本信息可通过页面内表单直接修改并保存，保存后页面显示新值。
- [x] 每个事实分区可通过「手动添加」直接新增条目，保存后条目出现在该分区。
- [x] 每条事实可通过「编辑」直接修改类型/标题/内容/标签/证据状态/可见性，保存后就地更新。
- [x] 直接编辑默认证据状态为待核实（BR-D09），仅当用户显式选择才标记已核实。
- [x] 对话入口（对话维护资料、对话编辑、对话添加、对话更新）保留且仍可用。
- [x] pnpm --dir ui run build、pnpm --dir ui test、pnpm --dir ui run lint 与 archkit inspect . 全部通过。

## Implementation

- types：新增 `ProfileFactInput`，把直接编辑写入的字段（类型/标题/内容/标签/证据/可见性）与对话解析结果 `ProposedFactChange` 分开。
- api：抽出 `createFactRecord`；新增 `createFactManually`（POST /profile/facts，来源标记「手动录入」）；`updateFact` 在 mock 数据源找不到条目时按 PATCH 语义返回合并结果，使对话新建的条目也能被继续直接编辑。
- lib/profile.ts：统一 `FACT_TYPE_LABEL`、`EVIDENCE_STATUS_LABEL`、`FACT_VISIBILITY_LABEL`、`FACT_TYPE_ORDER`；`profile-assistant` 改用共享文案，消除两份类型标签。
- 新增 `profile-basics-form.tsx`（姓名/头衔/邮箱/电话/城市 + 链接增删）与 `profile-fact-form.tsx`（新增与修正共用字段，证据状态默认待核实）。
- `profile-workspace.tsx`：基本信息卡新增「编辑」，每个分区新增「手动添加」，每条事实新增「编辑」；保存后新条目置顶、更新条目就地刷新并高亮 2.5s；原有对话入口与 `ProfileAssistant` 完全保留，两条路径写同一份页面状态。
- 表单控件沿用事实卡片与结构化编辑器已有的 `border-input` / `focus:ring-ring/30` 与 primary/border 按钮样式，未引入原型之外的视觉规则。
