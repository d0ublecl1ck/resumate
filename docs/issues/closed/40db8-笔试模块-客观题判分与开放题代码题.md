# 笔试模块：客观题判分与开放题代码题

## Background

`ui/src/features/interview/written-screen.tsx` 展示客观题/开放题/代码题三种题型与判分，但题目、判分与解析全部是文件内 mock，没有后端。issue 40db8 把这屏接到真实功能。

## Scope

- 新增 `backend/app/modules/quiz/**`：抽题、作答、判分、提交。
- 客观题（单选/多选/判断）：服务端确定性判分，答案键只落库、不下发。
- 开放题：复用 `app.modules.interview.llm.chat_json` 评分 + 逐字原话证据，风格与面试报告一致。
- 代码题：只提交文本 + 模型静态评审，**不执行任何用户代码**。
- 接口：`POST /quiz/attempts`、`POST /quiz/attempts/{id}/answers`、`POST /quiz/attempts/{id}/submit`、`GET /quiz/attempts/{id}`。
- 题目来源：开放题优先从题库 `bank_questions` 按岗位抽取，为空时回落内置种子题；客观题与代码题来自内置种子题。
- 前端 `written-screen.tsx` 接真接口，三种题型可作答、可提交、可看判分与解析；i18n 中英同步。
- 表 `quiz_attempts` / `quiz_answers`。

## Non-goals

- 不做任何形式的代码执行、沙箱或模拟运行（安全红线）。
- 不新增 RBAC 权限码，沿用面试模块的 `jd:read` / `jd:write`。
- 不改题库模块本身，只通过适配层读取。

## Acceptance Criteria

- [x] 客观题判分口径服务端确定性执行，答案键不出现在抽题响应中。
- [x] 多选策略明确：完全一致满分；无错选的正确子集半分（向下取整）；任错选或未选 0 分。
- [x] 重复提交同一作答幂等（同一 `question_id` + `idempotency_key` 只落一条）。
- [x] 未提交时 GET 返回 `result: null`，提交后幂等返回冻结总分。
- [x] 代码题响应 `executed: false`，且真实文件系统哨兵证明提交的代码没有被执行。
- [x] 开放题只采纳逐字引用作答原文的证据；无证据维度不给分。
- [x] 前端整链路（抽题→作答→提交→看分数）可由无头浏览器真点通。

## Implementation

- 后端模块：`backend/app/modules/quiz/{models,schemas,seed,dao,service,api}.py`。
  - `service.grade_objective` 是纯函数判分口径；开放题/代码题复用 `app.modules.interview.llm.chat_json`。
  - `seed.py` 提供客观题/开放题/代码题种子；`dao.list_bank_open_questions` 是题库适配层。
  - 代码题只把提交文本交给模型做静态评审，模块不导入任何执行/子进程能力，`feedback.executed=false` 与响应 `executed=false` 双重落库。
- 路由注册：`backend/app/main.py`（只加了 quiz import 与 include_router）。
- 迁移：`backend/migrations/versions/a3f6c9e2d5b8_create_quiz_tables.py`，`down_revision=4fd011c03ba5`（创建时的最新 head）。
- 前端：`ui/src/lib/quiz-api.ts`、`ui/src/features/interview/written-screen.tsx`、`ui/src/i18n/locales/{zh-CN,en}/interviewWritten.ts`；`ui/src/App.tsx` 只加了 `/interview/written` 路由与对应 import。
