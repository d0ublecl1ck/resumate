# 提交元数据身份占位（5 个 tip 提交的作者邮箱）

## Background

第二轮历史改写（dc926）之后新建的 5 个提交使用了本机 git 配置的真实作者身份（句柄 + 个人邮箱），个人邮箱属于实质泄漏。这些提交都在各分支 tip 上（无后代），因此只重写它们即可，既清掉邮箱又不动其余 388 个提交的 SHA。

## Scope

- 用 `git filter-repo` 的 `--name-callback` / `--email-callback` 只把作者句柄与个人邮箱替换为占位，空邮箱与历史昵称保持原样。
- 同步在提交信息里替换句柄与个人邮箱（`--replace-message`）。
- 在 `docs/history-commit-map.tsv` 头部补第三轮说明，并在末尾以注释列出受影响的 5 个提交的旧 SHA、新 SHA 与 subject。

## Non-goals

- 不改历史昵称 `anan`（无邮箱，根提交作者；改它会让全部 393 个提交换 SHA）。
- 不改业务代码、测试与门禁逻辑。

## Acceptance Criteria

- [x] 只有 5 个提交换 SHA，其余 388 个旧 SHA 保持不变（实测对比）。
- [x] `git log --all --format='%an <%ae>' | sort -u` 只剩占位身份与历史昵称，无个人邮箱。
- [x] 提交信息里个人邮箱零命中；学校名/教师名/真实姓名仍零命中。
- [x] `git lfs fsck` 退出码 0、`git lfs ls-files` = 365、S1 PDF 头 `%PDF`；三个工作树干净。
- [x] 门禁与三套测试通过；两条分支 `--force-with-lease` 推送成功且 `HEAD == origin/…`。

## Implementation

- 改写前记录 `git rev-list main | sort`（393 行）；用 `git filter-repo` 的 `--name-callback`（作者句柄 → 占位）与 `--email-callback`（个人邮箱 → 占位，空邮箱不动）只替换这 5 个 tip 提交的作者元数据；`--replace-message` 规则文件只放 /tmp，不入库。`anan` 与空邮箱保持原样。
- 改写后重挂 origin remote 与两个 linked worktree；`docs/history-commit-map.tsv` 头部补第三轮说明、末尾补这 5 个提交的旧/新 SHA 与 subject。

## Verification

- SHA 对比：改写后 `git rev-list main` 仍为 393 行，与改写前的交集为 **388** 行；差异正好是那 5 个 tip 提交（`32f5c77`/`aec3a59`/`6fbe2a7`/`8f74525`/`0410ae0`），未受影响的 `afe7019` 等 SHA 逐字不变。
- `git log --all --format='%an <%ae>' | sort -u` → 仅 `example-org <example-org@example.com>` 与 `anan <>`；提交信息里个人邮箱 0 命中；学校名/教师名/真实姓名仍 0 命中。
- `git lfs fsck` → `Git LFS fsck OK`（退出码 0）；`git lfs ls-files` = 365；`head -c 4 docs/deliverables/S1-方案概要.pdf` = `%PDF`。
- 三个工作树（主工作区、`zj-fwwb-2026`、`conversation-fixes`）`git status --short` 均为空。
- 门禁与三套测试通过；两条分支 `--force-with-lease` 推送成功。
