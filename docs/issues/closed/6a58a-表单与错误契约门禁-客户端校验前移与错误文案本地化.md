# 表单与错误契约门禁：客户端校验前移与错误文案本地化

## Background

注册流程暴露两个叠加缺陷：

- 前端没有任何校验层。`ui/src/components/login-form.tsx` 手写 `<form noValidate>` 与裸 `<input>`，提交时只 `trim()`；`noValidate` 关掉了浏览器原生校验，唯一校验点变成后端 `RegisterRequest.email: EmailStr`。
- 后端错误被原样直出。FastAPI 的 `RequestValidationError` 处理器把 pydantic 英文 `msg` 拼进 `ApiError.message`，前端 `ui/src/pages/login.tsx` 的 `messageFor` 对未映射的机器错误码兜底 `return cause.message`，于是界面出现英文 `value is not a valid email address: ...`。

项目已安装 `react-hook-form`、`@hookform/resolvers`、`zod`，但 `ui/src` 对三者零引用；`ui/src/components/ui/` 也没有把 schema 校验接进字段的共享原语。根因不是「缺少开源表单」，而是「校验没有前移、错误出口没有本地化收口」。

这类约束此前只存在于文档与流程说明里，靠人或 agent 自觉执行，没有机器强制，因此同类问题会复发。

## Scope

- 新增 `quality-gates/gates/ui-form-contract.js`，包含两条项目语义判定：
  - 表单契约：含命名字段（`name="..."`）的 `<form>` 必须接入 schema 驱动校验（`useForm(` 或 `zodResolver(`），未接入时不得用 `noValidate` 冒充校验。
  - 错误契约：引用 `ApiRequestError` 的文件不得把错误对象的 `message` 直接作为用户可见文案。
- 支持行内显式豁免标记（`form-allow`、`error-message-allow`），豁免进仓库、进 review。
- 为当前基线中的遗留站点补显式豁免，保证门禁常绿。
- 把同一判定提炼为可复用的门禁模板（与仓库内 gate 判定一致，含配置项与豁免标记），供其他项目直接复用。

## Non-goals

- 不在本 issue 内把 `login-form.tsx` 迁移到 `react-hook-form` + `zod`（属独立改造，需先走原型与 Storybook 确认）。
- 不新增或改造页面视觉与交互。
- 不修改其他既有门禁，也不改动 `archkit` 官方门禁副本。

## Implementation

- 新增 `quality-gates/gates/ui-form-contract.js`：两条判定 + 行内豁免标记；带命名字段的表单才触发表单契约，聊天输入框这类无名字段的 `<form>` 不误报。
- `ui/src/components/login-form.tsx`：加 `form-allow` 显式豁免，记录遗留表单尚未接入客户端校验。
- `ui/src/pages/login.tsx`：在 `return cause.message` 行加 `error-message-allow` 显式豁免，记录待把机器错误码映射到 i18n 文案。
- 可复用门禁模板：与仓库内 gate 同一判定，额外提供 `includeDirs` / `ignoreDirs` / `allow` / `apiErrorNames` / 豁免标记名等配置项。
