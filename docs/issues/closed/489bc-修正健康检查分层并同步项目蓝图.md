# 修正健康检查分层并同步项目蓝图

## Background

健康检查路由直接执行数据库 SQL，违反模块制蓝图的薄路由边界；项目设计文档仍为模板。

## Scope

- 将数据库探活移至 app/core/db.py 的同步依赖，health 路由仅返回响应 schema。
- 用真实 SQLite 连接验证健康检查成功及数据库故障路径。
- 同步 docs/design.md、README 和 AGENTS 的过期线索。

## Non-goals

- 不引入业务模块、数据库迁移或新的 HTTP 错误协议。

## Acceptance Criteria

- [x] 路由响应函数可独立调用，不接收数据库会话。
- [x] GET /health/ 成功返回 200 和原响应，数据库不可用时返回 500。
- [x] OpenAPI 保留健康检查响应模型。
- [x] 蓝图描述真实目录、依赖方向和未实现能力；项目门禁通过。

## Implementation

数据库查询移入 `app/core/db.py` 的同步 `check_database_connection` 依赖，继续复用 `get_db` 会话生命周期。健康检查路由只声明依赖并返回 `HealthResponse`。完善项目蓝图、根 README 和后端 README，替换 AGENTS 中已解决的模板线索。
