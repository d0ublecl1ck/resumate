# 响应式宽度浪费：工作区页面在宽视口下未吃满可用宽度

## Background

浏览器缩放到 70% 时 CSS 视口变宽（物理 1614px 窗口约等于 2305 CSS px），但工作区页面
主内容仍被钳在 1152px 并居中，左右各空出约 570px 死区，多出来的宽度完全没用上。

根因单一：`ui/src/components/app-shell.tsx` 里所有路由共用同一条 `main`：

```jsx
<main className="mx-auto w-full max-w-6xl flex-1 px-5 py-8 sm:px-8">{children}</main>
```

`max-w-6xl` = 72rem = 1152px。页面本身已经能伸缩：`ui/src/components/resume-editor.tsx`
的三栏用 `lg:grid-cols-[minmax(0,1.1fr)_minmax(0,1fr)_minmax(0,1.1fr)]`，外层给多少它就用多少。
瓶颈只在外壳这一处 max-width，缺的是「页面类型 → 宽度策略」的单一出处。

## Scope

- 在 `app-shell.tsx` 定义外壳宽度契约 `ShellWidth = "fluid" | "readable"`，每条路由的宽度
  在 `App.tsx` 路由表上显式声明，页面自身不写 `max-w-*`。
- `fluid`：不设上限，吃满侧栏之外的可用宽度，给多栏工作区用。
- `readable`：保留 `max-w-6xl`（72rem = 1152px）可读性上限，给文本/表单页用。
- 工作区型路由（fluid）：`/resumes/:id`、`/interview/:id`、`/interview/bank`、
  `/interview/growth`、`/interview/written`、`/interview/history`、`/profile`。
- 其余路由默认 readable：设置、认证页、版本历史、库列表、后台管理等。
- 补齐 `app-shell` 的宽度契约测试。

### 宽度策略

- 机制：`<AppShell width="fluid">` / `<AppShell width="readable">`。在 `App.tsx` 用两条布局
  路由把工作区型与阅读型分开声明，路由与宽度写在同一处，不会出现「路由改了宽度表忘了改」的漂移；
  不靠 `2xl:` 之类断点去猜页面类型。
- `fluid` 的数值策略：`main` 只有 `w-full`，宽度 = 视口 − 侧栏 − 内边距。1440 CSS px 时
  ≈1200px、1920 时 ≈1680px、2560 时 ≈2320px，缩放越大用得越多，不存在「越大越浪费」。
- `readable` 的数值策略与依据：上限 1152px。16px 基准字号下西文正文可读行宽约 65–75 字符，
  72rem 落在这个区间；中文正文约 36 字/行，也在舒适区间。设置、表单、版本历史这类单列内容
  超过这个宽度会拉长视线回扫、降低可读性，因此有意保留。
- 为什么不多给一层「fluid 也有个很宽的上限」：工作区的价值随宽度增长（三栏、双栏对照、表格列），
  而卡片/栅格内部的断点已经在页面层控制了列数；再在外壳加一个上限只会重新制造死区。

## Non-goals

- 不改任何页面内部的栅格、断点与卡片布局。
- 不改认证页：登录/注册走独立的 `AuthShell`，本就不经过 `AppShell`。
- 不引入按分辨率猜页面类型的断点式宽度。

## Acceptance Criteria

- [x] 工作区型 7 条路由的 `main` 无 `max-w-*`，宽度随视口单调增长。
- [x] 阅读/表单型路由保留 1152px 可读性上限。
- [x] 1440 / 1920 / 2560 CSS px 下 `scrollWidth <= clientWidth`（无横向滚动）。
- [x] `/resumes/:id` 三栏容器宽度等于 `main` 内容宽度（吃满，无二次钳制）。
- [x] `<lg` 移动端既有表现不变（侧栏隐藏、MobileNav、单栏切换）。
- [x] `pnpm -C ui test`、`pnpm -C ui exec tsc -b --noEmit`、`node quality-gates/run.js`、
      `archkit inspect .` 全部通过。

## Implementation

- `ui/src/components/app-shell.tsx`：新增 `ShellWidth = "fluid" | "readable"` 与单一出处
  `SHELL_WIDTH` 类名表；`AppShell` 增加 `width` 属性，默认 `readable`（保持既有页面不变），
  `main` 从固定 `max-w-6xl` 改为按档位取类名。
- `ui/src/App.tsx`：拆成两条布局路由。工作区型 7 条
  （`resumes/:id`、`interview/bank`、`interview/written`、`interview/growth`、
  `interview/history`、`interview/:id`、`profile`）用 `<AppShell width="fluid">`；
  其余路由走默认 `readable`。路由与宽度写在同一处，不会再出现「路由改了宽度表忘改」的漂移。
- `ui/src/storybook/screen.tsx`：`Screen` 增加 `width` 透传；工作区的 story
  （简历编辑器、profile、interview 的 bank/session/voice/report/growth/written/history）
  传 `width="fluid"`，Storybook 与真实路由表现一致。
- 新增 `ui/src/components/app-shell.test.tsx`：先红后绿，覆盖两档类名、默认档位与
  `/resumes/:id`、`/settings`、`/resumes/:id/versions` 的路由分类。
