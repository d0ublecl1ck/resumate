# 修复事实表单未提交即显示必填校验

## Background

`/profile` 的「手动添加」事实表单（`ui/src/components/profile-fact-form.tsx`）在打开瞬间、标题与内容都为空时，按钮旁就显示红色校验文案「标题与内容不能为空。」。根因是必填提示直接绑在 `!valid` 上，与「用户是否尝试过提交」无关；同时提交按钮在 `!valid` 时被禁用，用户无法表达一次「尝试提交 → 报错」的合法路径，只能在编辑已有事实时反复看到红字。

## Scope

- `ui/src/components/profile-fact-form.tsx`：区分 pristine 与已尝试提交；只有用户尝试提交且输入仍非法时才显示 `profile.factForm.required`，输入修正合法后立即消失。
- 提交按钮在非 busy 时可点击，让「尝试提交」这一动作可被表达；内容合法时正常保存。
- 补测试覆盖：pristine、只填标题提交、补齐内容保存三条路径。

## Non-goals

- 不改文案键与视觉令牌（沿用既有 `profile.factForm.required`）。
- 不重构为 `useForm` + `zodResolver`：该组件无 `<form>` 也无命名字段，不在 `ui-form-contract` 判定范围内。
- 不改后端校验与 Profile API。

## Acceptance Criteria

- [x] 表单刚打开（pristine）时页面不出现 `标题与内容不能为空。`
- [x] 只填标题、未填内容时点击提交，出现 `标题与内容不能为空。`
- [x] 补齐内容后提交成功，错误消失并写入新事实
- [x] `pnpm -C ui test` 通过

## Implementation

- `ui/src/components/profile-fact-form.tsx`：新增 `submitAttempted` 状态，`showRequired = submitAttempted && !valid`；只有用户点过提交且输入仍非法时才渲染 `profile.factForm.required`，输入补齐后立即消失。`save()` 先置 `submitAttempted` 再校验；提交按钮由 `disabled={!valid || busy}` 改为 `disabled={busy}`，让「尝试提交」这一动作可被表达。
- 测试：`ui/src/components/profile-workspace.test.tsx` 新增「新增事实表单未提交时不显示校验错误」「只填标题提交才显示校验错误，补齐内容后保存并消失」。
- 文案键、视觉令牌与后端校验均未改动。
