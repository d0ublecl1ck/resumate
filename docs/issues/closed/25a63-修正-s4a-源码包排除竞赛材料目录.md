# 修正 S4A 源码包排除竞赛材料目录

## Background

`sync-deliverables.sh` 用 `git archive HEAD` 生成 S4A 源码包，脚本自身的验收口径写明「源码包不含 docs/competition/**」。但 `docs/competition/` 在 ef128 里被纳入版本管理后，这条排除实际失效：S4A 包从 36.7 MB 涨到 110.1 MB，把竞赛过程材料（含历史 PPTX 备份与演示视频）一起打了进去。这是实现与验收口径不一致，需要修正。

## Scope

- 修改 `docs/competition/zj-fwwb-2026/sync-deliverables.sh` 的 `git archive` 调用，显式排除 `docs/competition`。
- 重跑同步脚本并确认 S4A 包回到约 36.7 MB；重打桌面提交包（rar）。

## Non-goals

- 不改动其他打包内容与目录结构（除该排除规则外）。
- 不改业务代码、测试与门禁逻辑。

## Acceptance Criteria

- [x] 脚本 `git archive` 行带 `':(exclude)docs/competition'` 与 `':(exclude)docs/deliverables'`。
- [x] 重跑同步后 S4A-源码包.zip 约 36–38 MB，且包内不含 `docs/competition/` 与 `docs/deliverables/`。
- [x] `node quality-gates/run.js` 与 `archkit inspect .` 通过；三套测试通过。
- [x] 提交/关单/推送/合并流程完成，`HEAD == origin/main`。

## Implementation

- `sync-deliverables.sh` 的 `git archive` 增加两条排除：`':(exclude)docs/competition'` 与 `':(exclude)docs/deliverables'`。
- 依据：`docs/competition/` 是竞赛过程材料（另有交付渠道），`docs/deliverables/` 是已单独提交的成品副本，两者塞进源码包都属重复投放；`docs/e2e/` 作为端到端证据按脚本口径保留在包内。

## Verification

- 重跑 `sync-deliverables.sh`：S4A-源码包.zip = `36,713,767` B（修复前 110,137,085 B，含 deliverables 时 48,105,971 B），sha256 前 16 `c2fa83dc231c9971`。
- 包内校验：共 1247 条目；`docs/competition` 与 `docs/deliverables` 均不存在。
- `node quality-gates/run.js` → Quality gates passed（known stubs: 0）；`archkit inspect .` → Quality gates passed。
- 三套测试：backend 583 passed、agent-core 130 passed、ui 81 files / 649 tests passed。
