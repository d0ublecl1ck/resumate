# 清理公开仓库中的本机绝对路径并加门禁

## Background

仓库自 2026-09-29 起为公开仓库（`.freak` 有登记），规则要求新增文档、工单与示例不得写入本机绝对路径。但历史遗留仍在，且**没有任何门禁校验这条规则**，所以只能靠人工回溯：

- `docs/issues/closed/d59dd-修正-readme-已知边界-agent-run-已接真实端点-并补运行体安装前提.md:48` 写着真实路径 `/Users/<本机用户名>/.local/bin/resumate-agent`。
- `docs/issues/closed/1d43f-移除公开仓库中的本机路径与个人邮箱.md:43` 把被替换掉的原路径原样留在说明里（`（源目录 /Users/<本机用户名>/Documents/resumate）`）。

同类规则此前的执行方式是「人工跑一次 `git grep`」，没有作者会发现回归。

## Scope

- 清理上述两处真实本机绝对路径（改写为不带路径的描述）。
- 新增项目门禁 `quality-gates/gates/repo-private-paths.js`：扫描 Git 跟踪的文本文件，命中 `/Users/<用户名>/`、`C:\Users\<用户名>\` 这类真实绝对路径即失败。
- `.freak` 登记该规则已由门禁兜住。

## Non-goals

- 不改写 Git 历史（历史中的路径无法通过新提交抹除）。
- 不扫描仓库外文件、不检查未跟踪文件（`.gitignore` 覆盖的本地文件不属于公开面）。
- 不引入个人邮箱、内网 IP 等其它检查项（本次只收掉已确认会被公开的本机绝对路径）。

## Acceptance Criteria

- [x] 门禁先红后绿：加入门禁后先跑出上述两处命中，清理后再跑通过。
- [x] `git grep -nI -E "/Users/[A-Za-z0-9_.-]+/" -- .` 无命中。
- [x] 规则说明类引用（如反引号包住的 `/Users/`）不误报，`archkit inspect .` 通过。

## Implementation

- `quality-gates/gates/repo-private-paths.js`（新增，runner 自动发现 `gates/*.js`，无需注册）：
  - 用 `git ls-files -z` 取 Git 跟踪文件，逐个读取；跳过二进制（含 NUL）与超过 2 MiB 的文件。
  - 两个模式：`/Users/<用户名>/`（macOS 家目录）与 `C:\\Users\\<用户名>\\`（Windows 家目录）；`/Users/` 之后必须紧跟用户名与分隔符，因此「只引用规则本身」的写法不会误报。
  - 跳过门禁自身，避免正则字面量自命中。
- 清理两处真实路径：
  - `docs/issues/closed/d59dd-…-并补运行体安装前提.md:48`：`which resumate-agent` 的观测值改为 `<uv tool 的 bin 目录>/resumate-agent`。
  - `docs/issues/closed/1d43f-…-与个人邮箱.md:43`：把「源目录 + 本机绝对路径」改写为「源目录为仓库外的 v0 导出工程」。
- `docs/design.md` 的门禁清单补上新门禁与该公开仓库约束；`.freak` 登记该规则已由门禁兜住，并注明个人邮箱/内网 IP 仍未纳入。
