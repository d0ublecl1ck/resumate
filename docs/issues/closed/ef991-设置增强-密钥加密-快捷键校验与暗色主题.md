# 设置增强：密钥加密、快捷键校验与暗色主题

## Background

一期（85294）落地了系统设置 API 与前端联调，但留下三项可做而未做的取舍：模型 API Key 未加密落库、快捷键只能只读、theme 只有持久化没有视觉应用（`ui/src/index.css` 缺少 `.dark` 令牌）。本期补齐。

## Scope

- API Key 静态加密：新增 `SETTINGS_SECRET_KEY` 配置，用 Fernet 加密 `model_config.apiKey` 后落库；响应仍只回 `keyConfigured`；解密失败按未配置处理，不抛明文、不 500。
- 快捷键冲突校验：`PATCH /settings` 收到重复按键映射时返回 422，错误信息点名占用该按键的动作；响应保留 `conflict` 标记用于历史数据展示。
- 快捷键编辑：`SettingsForm` 支持逐条编辑按键并随偏好一起保存。
- 暗色主题：在 `ui/src/index.css` 定义 `.dark` 令牌（由现有 oklch 浅色调色板推导），新增 `ThemeSync` 依偏好为 `<html>` 切换 `.dark`；先补充 `ui/prototypes/index.html` 登记暗色令牌与设置页交互态。

## Non-goals

- 不做 PAT 鉴权强制与访问日志（属下一期「开放接入」）。
- 不做备份导入导出（属下一期）。
- 不引入新的设计语言；暗色令牌只做同一调色板的明度反转，并在原型中登记。

## Acceptance Criteria

- [x] `PUT /models/config` 后数据库 `apiKey` 为密文，响应与日志不含明文；密钥变更导致解密失败时不 500。
- [x] `PATCH /settings` 提交冲突快捷键返回 422，且不覆盖已有映射。
- [x] 保存非冲突快捷键后回读一致。
- [x] 选择暗色主题后 `<html>` 带 `.dark`，刷新后保持；`index.css` 定义完整 `.dark` 令牌。
- [x] `ui/prototypes/index.html` 登记暗色令牌与设置页交互态。
- [x] 后端 pytest、前端 build/test/lint、`archkit inspect .` 全部通过。

## Implementation

- 加密：`app/core/config.py` 新增 `settings_secret_key`（env `SETTINGS_SECRET_KEY`）并写入 `.env.example`；`service._fernet` 用 SHA-256 派生 Fernet key，`_encrypt_secret` 落库时加 `fernet:` 前缀，`_decrypt_secret` 兼容历史明文并对损坏密文返回 `None`。
- `PUT /models/config` 存密文；`_model_config` 仍只回 `keyConfigured`；`POST /models/config:test` 使用解密后的凭证外呼，解密失败按未配置处理，不抛 500、不回显明文。
- 快捷键校验：`_normalize_keys` + `_validate_shortcuts` 在 `PATCH /settings` 写入前检测重复按键，返回 422 且点名占用动作；响应阶段用 `Counter` 给历史重复项打 `conflict=true`。
- 前端快捷键：`settings-form.tsx` 每条形如输入框，随偏好一起保存；失败展示后端错误；`types.ts` 的 `UserPreferencesUpdate` 纳入 `shortcuts`。
- 主题：`index.css` 新增 `.dark` 令牌（同调色板明度反转，coral/cobalt/gold 不变）；新增 `theme-sync.tsx` 依 `["preferences"]` 缓存切换 `<html class="dark">`，挂载于 `AppShell`；`ui/prototypes/index.html` 增加「设计补充」区块登记暗色令牌与设置页交互态。
