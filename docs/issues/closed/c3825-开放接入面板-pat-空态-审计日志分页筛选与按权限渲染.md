# 开放接入面板：PAT 空态、审计日志分页筛选与按权限渲染

## Background

`/settings/access`（SCR-011 开放接入与访问审计）有三个缺口：

1. PAT 列表为空时区块只剩标题 + 创建按钮，没有任何空态提示。
2. `GET /access/logs`（`backend/app/modules/access/api.py` → `service.list_logs` → `dao.list_logs`）没有任何查询参数，一次性返回全量（实测 59 行全量渲染），前端也没有筛选/分页控件。
3. 前端不按 `access:read` / `access:write` 渲染权限态：无读权限仍显示 tab、发请求后只拿到通用 403；有读无写时创建/撤销入口未禁用。

仓库现状核对（与任务前提的差异）：`GET /resumes` 及其 service/dao/前端都没有分页，全仓不存在分页响应 envelope，只有 `app/core/deps.py` 的 `PaginationParams`（page/size，page>=1，size 1..100，默认 20）定义但未被任何端点使用。因此本工单不复用一个不存在的 envelope：`GET /access/logs` 响应体继续保持 `list[AccessLogResponse]` 裸数组，分页元数据通过 `X-Total-Count` 响应头传递。

## Scope

- 后端 `GET /access/logs`：新增 `page` / `size`（复用 `app/core/deps.py` 的 `get_pagination`，越界沿用既有 422 行为）、`purpose`、`result`、`q`（大小写不敏感匹配 `client_id` / `scope` / `resource`）查询参数；筛选后按 `at` 倒序分页；响应头写 `X-Total-Count`（筛选后的总条数）；响应体仍为裸数组；`access:read` 权限语义不变。
- 前端 `ui/src/lib/api.ts` / `types.ts`：为 `/access/logs` 写专用 fetcher（读取 `X-Total-Count`），不改动全局 `request()` 行为。
- 前端 `ui/src/pages/settings-access.tsx` + `ui/src/components/access-panel.tsx`：筛选栏（purpose / result / 关键字）+ 分页控件；筛选变更重置到第 1 页；PAT 与日志空态；日志加载/错误态；按 `access:read` 显示无权限态且不请求 `/access/logs`；按 `access:write` 禁用创建/撤销并说明原因。
- `ui/prototypes/index.html` SCR-011 屏同步新增可见状态。
- `docs/design.md` 与 `docs/user-stories/contracts.md` 同步契约（参数、响应头、响应体仍为裸数组）。

## Non-goals

- 不改后端 RBAC；`POST /access/tokens`、`POST /access/tokens/{id}/revoke`、`GET /.well-known/resume-agent` 的形状与权限不变。
- 不改 `/settings` 主面板、`/profile`、`/settings/backup`。
- 不动 `version-history`、`create-jd-modal`、`resume-picker-dialog` 等未迁移 Modal 原语的手写弹窗。

## Implementation

- `backend/app/modules/access/api.py`：`GET /access/logs` 注入 `Response`，新增 `purpose`、`result`（`AccessResult` Literal，非法值 422）、`q`（`max_length=200`）与 `PaginationParams`（`get_pagination`）依赖；把筛选后总条数写入 `X-Total-Count` 响应头，响应体仍是裸数组。
- `backend/app/modules/access/dao.py`：`list_logs` 改为返回 `(rows, total)`，按 `owner_id` + `purpose` / `result` / `q`（`ilike` 匹配 client_id/scope/resource）过滤，`count()` 求 total，按 `at` 倒序 + `id` 倒序稳定排序后 `offset/limit`。
- `backend/app/modules/access/service.py`：`list_logs` 透传筛选与分页参数，返回 `(list[AccessLogResponse], total)`。
- `backend/tests/test_access.py`：新增 6 条（分页 + `X-Total-Count`、`at` 倒序、purpose/result 筛选、关键字大小写不敏感、越界/非法参数 422 与未知 purpose 规范化、缺 `access:read` 时 403）；原有裸数组断言保持不变。
- `ui/src/lib/api-client.ts`：抽出 `send` + `parseJson`，新增 `requestWithResponse`（返回 `{ data, response }`）；`request` 的行为与返回形状不变。
- `ui/src/lib/api.ts` / `ui/src/lib/types.ts`：新增 `AccessLogQuery` / `AccessLogPage`；`listAccessLogs` 拼 `page/size/purpose/result/q` 并读 `X-Total-Count`，缺失时为 `null`。
- `ui/src/components/access-panel.tsx`：新增筛选栏（用途 / 结果 / 关键字）、分页控件、PAT 空态、日志空态/筛选空态/加载/错误态；`canWrite=false` 时创建与撤销禁用并显示原因。
- `ui/src/pages/settings-access.tsx`：`useCurrentUser` 读取权限；缺 `access:read` 显示 forbidden 状态块且 `pats`/`logs` 查询 `enabled:false`；筛选变更 `setPage(1)`。
- `ui/src/mocks/handlers.ts`：`GET /api/access/logs` mock 支持分页/筛选并回 `X-Total-Count`；`AUTH_USER` 补 `access:read` / `access:write`。
- `ui/src/i18n/locales/{zh-CN,en}/settings.ts`：补 `access.*`、`pat.empty.*`、`accessLog.{loading,errorTitle,errorDescription,empty.*,emptyFiltered.*,filters.*,pagination.*}`。
- `ui/prototypes/index.html`：`#screen-settings` states 登记权限态 / PAT 空态 / 筛选分页 / 日志空态 / 日志错误态。
- `docs/design.md`、`docs/user-stories/contracts.md`：记录查询参数、`X-Total-Count` 与「响应体仍为裸数组」。

用 headless Chromium（Playwright，`locale="zh-CN"`，管理员会话）对真实开发栈跑通，只做读取与路由伪造，**未执行创建/撤销令牌等破坏性写操作**；11 条断言全部通过：

- 日志分页控件出现并显示总数；点「下一页」后首行时间从 `10-07 18:09` 变为 `10-07 17:51`，列表内容确实变化。
- 用途筛选（`run_token_scope`）：请求带 `page=1&purpose=run_token_scope`，页码回到第 1 页，当前页 20 行全部为「运行令牌权限校验」。
- 结果筛选（`allowed`，真实库无该结果）：显示「没有符合筛选条件的记录」空态。
- 关键字筛选（`zzz-no-match-zzz`）：显示筛选空态；清空后列表恢复。
- 伪造 `GET /api/access/tokens` 返回 `[]`：显示「还没有个人访问令牌」空态。
- 伪造 `GET /auth/me` 权限为 `["account:read"]`：显示「无权访问开放接入」，且全程 **0 次** `/access/logs` 请求。
- 权限为 `["access:read"]`：创建入口 `disabled`，显示「当前账号只有读取权限，创建与撤销入口已停用。」
- Vite 代理下 `X-Total-Count` 实测可读（63），未触发客户端分页退化路径。
