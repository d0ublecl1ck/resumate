# 简历编辑器手动保存接真实端点

## Background

`ui/src/components/resume-editor.tsx` 的 `flush()` 只做两件事：把本地 `saveState` 切成 `saving`，再在 500ms 后切成 `committed`。它**不发任何请求**；结构化编辑（`structured-editor.tsx`）的所有改动只落到 `useState`；`ui/src/lib/api.ts` 里根本没有 `updateDocument`。

于是实际行为是：改完点「保存（flush）」→ 徽标走一遍「保存中 → 已保存版本」→ **刷新页面全部丢失，且没有任何报错**。后端 `PUT /resumes/{resume_id}/document`（`backend/app/modules/resume/api.py:129`）早已实现，服务层 `update_document` 还带 `base_version_id` 乐观锁与「内容未变则不生成新版本」的短路，缺的只是前端调用。

同一屏的「导出」按钮也是空按钮（无 `onClick`、后端也没有简历导出端点），但那是独立缺口，本次只登记不改。

## Scope

- `ui/src/lib/api.ts`：新增 `updateDocument(id, { document, baseVersionId, message })` → `PUT /resumes/{id}/document`。
- `ui/src/lib/resume-document.ts`：新增 `documentSaveErrorMessage`，把机器错误码映射成 i18n 文案（`BASE_VERSION_STALE` / `VALIDATION_FAILED` / `FORBIDDEN|UNAUTHENTICATED` / `NETWORK_ERROR` / 兜底），形状沿用既有的 `lib/resume-create.ts`。
- `ui/src/components/resume-editor.tsx`：`flush()` 改为真实请求——成功后用服务端权威 `saveState` 与 `document`、并失效 `["resume", id]` 与 `["resumes"]` 重取基线；失败回滚徽标并在上下文条下方就地 `role="alert"` 报错；保存中禁用按钮并置 `aria-busy`。
- i18n：`zh-CN/resume.ts` 与 `en/resume.ts` 同步新增 `resume.editor.manualSaveMessage` 与 `resume.editor.saveErrors.*`。
- `ui/src/mocks/handlers.ts`：补 `PUT /api/resumes/:id/document` 处理器，镜像后端的乐观锁与短路行为，供 Storybook 与测试共用。
- `ui/prototypes/index.html` 的 `#screen-editor`：补保存成功 / 基线过期 / 其它失败的状态与失败态视觉示例。
- `README.md`：更正「不可变版本、任意两版比较、恢复、导出 | 已实现」这个把导出算进去的错误口径，并同步前端测试计数。

## Non-goals

- 不做自动保存，也不做离开页面前的未保存提醒（登记在 `.freak`，本次只有手动 flush 一条落库路径）。
- 不做简历导出：后端没有端点，README 改为标注「未实现」。
- 不改后端：`PUT /resumes/{id}/document` 与 `BASE_VERSION_STALE` 已存在且行为符合需要。
- 不做离线队列 / 冲突自动重排（`REBASE_CONFLICT` 属于 Agent 落库链路）。

## Acceptance Criteria

- [x] 点保存发出 `PUT /resumes/{id}/document`，请求体含整份 `document`、`baseVersionId` 与版本 `message`。
- [x] 保存成功后徽标取服务端 `saveState`，并失效 `["resume", id]` 让基线重新取服务端值。
- [x] 没有改动时保存按钮不可用且不发请求。
- [x] `BASE_VERSION_STALE` 时就地展示 i18n 冲突文案，不透出服务端原始 message，也不显示「已保存」。
- [x] 网络失败给 i18n 文案并保持按钮可重试。
- [x] 原型对应屏同步更新；README 导出口径更正；`pnpm -C ui test`、`pnpm -C ui build`、`archkit inspect .` 通过。

## Implementation

- `lib/api.ts`：`updateDocument` 走 `request<Resume>`，请求体字段用后端的 camelCase 别名（`baseVersionId` / `message`）。
- `lib/resume-document.ts`：与 `lib/resume-create.ts` 同形状的键映射，逐码给文案，绝不回显服务端 message。
- `components/resume-editor.tsx`：`flush()` 变成 async；`saving` 期间不可重入，失败时 `setSaveState(resume.saveState)` 回滚到进入本次保存前的状态，本地草稿 `doc` 不丢。
- `mocks/handlers.ts`：`baseVersionId` 与 fixture 的 `currentVersionId` 不一致时返回 409 `BASE_VERSION_STALE`（带 `latestVersionId`），一致时回写文档并置 `saveState: "committed"`。
- 原型 `#screen-editor`：上下文条下方渲染一条失败态示例（coral 描边 + `role="alert"`），状态清单补保存成功、基线过期、校验 / 权限 / 网络失败、以及「导出仍无端点」的已知缺口。
- README：`不可变版本、任意两版比较、恢复、导出` 拆成两行，导出单独标注未实现；结构化编辑一行补「手动编辑经 `PUT /resumes/{id}/document` 落库并生成 manual 版本」；测试计数 34 files / 254 passed → 35 files / 259 passed。
- `.freak`：登记导出按钮无端点，以及手动编辑没有自动保存与离开提醒。
