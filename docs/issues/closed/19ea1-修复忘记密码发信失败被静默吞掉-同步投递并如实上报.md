# 修复忘记密码发信失败被静默吞掉：同步投递并如实上报

## Background

`POST /auth/password/forgot` 把发信塞进 FastAPI `BackgroundTask`：请求先返回 `202 {"status":"reset_sent"}`，后台任务随后抛错，错误只进日志。后果是**产品诚实性缺陷**：SMTP 未配置或发不出去时，界面依旧显示「重置邮件已发送」，用户以为收到邮件其实没有。2026-10-09 用户亲身遇到，后端日志实测证据：

```
File "backend/app/modules/auth/mailer.py", line 47, in send_password_reset_email
RuntimeError: SMTP 未配置：请设置 SMTP_HOST 与 SMTP_FROM_EMAIL
```

同一个坑在注册验证邮件（register / resend）也存在，但本 Issue 按用户指定只修忘记密码这一条；验证邮件链路保持现状，另行登记。

**决策一（枚举风险取舍，必须明写）**：同步投递后，只有在**发信链路本身故障**时，已注册邮箱才会拿到 502，而未注册邮箱始终 202。因此在一个 SMTP 正常工作的环境里，接口仍不可用于枚举；但当攻击者能让 SMTP 故障（或服务本来就没配 SMTP）时，502 与 202 的差异会泄漏「该邮箱已注册」。这是为了让调用方知道发信真失败而**接受的取舍**；另一条路（继续静默 202）等于把「已发送」假象留给所有用户，与本次修复目标直接冲突。若未来不可接受，正确解法是引入异步投递状态 + 通用「投递进行中」文案，而不是回到静默成功。

**决策二（冷却与令牌回滚）**：发信失败时删除本次签发的重置令牌与 lookup 记录，并清掉本次冷却。依据：若保留冷却，用户第一次失败后第二次点击会命中冷却分支、返回 202 且不发信，等于把同一个「假成功」延后一次点击复现。失败意味着邮件未送达，令牌无人持有，删除安全。发送小时配额不回滚，避免把失败重试变成对 SMTP 的放大攻击。

## Scope

**后端（`backend/app/modules/auth/` 与 `app/shared/errors.py`）**

- `POST /auth/password/forgot` 改为**同步投递**：命中账号并拿到 link 后先发信再返回，成功 202，失败 502。
- 新增机器错误码 `MAIL_DELIVERY_FAILED`（502）与异常类 `MailDeliveryFailed`。
- 失败时写日志，包含目标邮箱与失败原因；HTTP 响应只回通用中文文案，不含 SMTP 凭据与原始异常堆栈。
- 发信失败时释放本次冷却与刚签发的令牌，让用户重试真的会再次投递，而不是下一次点击立刻又回到静默 202。
- 未知邮箱行为不变：不生成 link、不调用 mailer、返回 202。

**前端（`ui/`）**

- `lib/resend.ts`：`MAIL_DELIVERY_FAILED` 经机器错误码映射到 i18n 文案，不直出后端 message。
- `lib/types.ts`：`MachineErrorCode` 增加 `MAIL_DELIVERY_FAILED`。
- `i18n/locales/{zh-CN,en}/auth.ts`：新增 `errors.mailDeliveryFailed`，两侧键结构一致。
- 忘记密码页：失败分支显示「邮件发送失败」文案，不再显示「已发送」（页面/组件结构已支持，仅补错误码映射与文案）。
- 测试：正/负向断言——期望 i18n 文案出现，且后端原始 message 关键字（如 `SMTP`）不出现。

## Non-goals

- 不改未知邮箱、冷却中、超配额的静默 202 契约。
- 不改注册 / 重发验证邮件的发信方式（仍为 BackgroundTask）。
- 不引入 SMTP 重试队列、退信处理或异步投递状态查询。
- 不新增数据库迁移。

## Acceptance Criteria

- [x] 后端：已知邮箱 + 发信成功 → 202 `reset_sent`，mailer 被调用一次。
- [x] 后端：已知邮箱 + mailer 抛错 → 502 `MAIL_DELIVERY_FAILED`；响应体不含 SMTP 凭据、原始异常类名或堆栈。
- [x] 后端：未知邮箱 → 202，且 mailer 完全不被调用。
- [x] 后端：发信失败写日志，含目标邮箱与失败原因。
- [x] 后端：发信失败后重试会再次尝试投递（冷却已释放），成功则 202。
- [x] 前端：收到 `MAIL_DELIVERY_FAILED` 显示 i18n 错误文案，不显示「已发送」，不泄漏后端 message。
- [x] i18n：zh-CN 与 en 键结构一致，en 无残留中文。
- [x] `pytest` / `pnpm -C ui test` / `pnpm -C ui exec tsc -b --noEmit` / `archkit inspect .` 全部通过。
- [x] 真实 HTTP：临时端口 8001 + 本机 2525 收件器 → 202 且邮件落盘；SMTP 指到 2599 → 502 且响应无凭据/堆栈。

## Implementation

**后端**

- `app/shared/errors.py`：新增 `ErrorCode.MAIL_DELIVERY_FAILED` 与 `MailDeliveryFailed(ApiException)`（`status_code = 502`）。
- `app/modules/auth/api.py`：`forgot_password` 去掉 `BackgroundTasks`，拿到 link 后同步 `mailer.send_password_reset_email(...)`；捕获异常后 `logger.warning`（含目标邮箱、异常类名与原因，`exc_info=True` 把堆栈留在服务端日志），释放回滚，再抛 `MailDeliveryFailed("邮件发送失败，请稍后重试或联系管理员")`。HTTP 响应只回通用文案。
- `app/modules/auth/service.py`：`PendingPasswordReset` 增加内部字段 `token`；新增 `release_failed_reset(client, email, token)`。
- `app/modules/auth/password_reset_store.py`：新增 `discard_reset(email, token)`，删除令牌、lookup 与冷却三条 key。

**前端**

- `ui/src/lib/types.ts`：`MachineErrorCode` 增加 `MAIL_DELIVERY_FAILED`。
- `ui/src/lib/resend.ts`：机器码映射到 `auth.errors.mailDeliveryFailed`。
- `ui/src/i18n/locales/zh-CN/auth.ts`：新增 `errors.mailDeliveryFailed: "邮件发送失败，请稍后重试或联系管理员。"`。
- `ui/src/i18n/locales/en/auth.ts`：同键位新增 `"We could not send the email. Try again later or contact an administrator."`。
- `ui/src/pages/forgot-password.test.tsx`：新增正/负向断言用例。

**接口契约对照**

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| 已知邮箱 + 投递成功 | 202 `reset_sent` | 202 `reset_sent`（不变） |
| 已知邮箱 + 投递失败 | 202 `reset_sent`（假成功，仅日志报错） | 502 `{"code":"MAIL_DELIVERY_FAILED","message":"邮件发送失败，请稍后重试或联系管理员"}` |
| 未知邮箱 / 冷却中 / 超配额 | 202 `reset_sent` 且不发信 | 202 `reset_sent` 且不发信（不变） |
