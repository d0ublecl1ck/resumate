# 删除模型配置的目录来源提示文案

## Background

「设置 → 模型配置」底部的 `目录来源：{{source}}` / `Catalog source: {{source}}` 提示行（`ui/src/components/settings-form.tsx`）把后端 `GET /models/catalog` 返回的 `source` 直接渲染给用户。该行只暴露内部数据来源（固定为 models.dev 快照），对用户配置模型没有帮助，与设置表单其余部分的密度也不一致，属于需要从生产界面移除的冗余提示。

## Scope

- 删除 `ui/src/components/settings-form.tsx` 中 `catalogSource` 取数变量与该提示行的渲染。
- 删除 `ui/src/i18n/locales/zh-CN/settings.ts` 与 `ui/src/i18n/locales/en/settings.ts` 的 `settings.model.catalogSource` 词条，保持两种语言键结构一致。
- 更新 `ui/src/components/settings-form.test.tsx` 与 `ui/src/components/settings-form.stories.test.tsx`：移除对该提示文案的正向断言，改为负向断言（界面不再出现 `目录来源` / `Catalog source`）。

## Non-goals

- 不改 `GET /models/catalog` 接口与后端 `source` 字段；`ui/src/lib/types.ts` 的契约注释保留。
- 不改 Endpoint、Provider / Model 下拉、测试连接逻辑，也不改模型目录白名单。
- 不改 `ui/prototypes/index.html`：原型 `#screen-settings` 本就没有登记这一行。

## Acceptance Criteria

- [x] `settings.model.catalogSource` 词条在 zh-CN 与 en 两个命名空间中均已删除，且键结构保持一致。
- [x] `ui/src` 中不再有该提示行的生产渲染引用（`catalogSource` 变量与 `t("settings.model.catalogSource")` 调用均已移除）。
- [x] 两个测试文件改为负向断言，`pnpm -C ui test` 通过。
- [x] `archkit inspect .` 与 `node quality-gates/run.js` 通过。

## Implementation

- `ui/src/components/settings-form.tsx`：删除 `const catalogSource = catalogQuery.data?.source` 与底部的整行渲染 `{catalogSource ? <p …>{t("settings.model.catalogSource", { source: catalogSource })}</p> : null}`；目录查询、Provider / Model 选项与其余表单逻辑不变。
- `ui/src/i18n/locales/zh-CN/settings.ts`、`ui/src/i18n/locales/en/settings.ts`：删除 `settings.model.catalogSource` 词条（`目录来源：{{source}}` / `Catalog source: {{source}}`），两种语言的键结构保持同步。
- `ui/src/components/settings-form.test.tsx`：用例名改为「从模型目录加载 provider 与 model，且不再显示目录来源」，去掉对提示文案的正向等待，补一条负向断言 `expect(screen.queryByText(/目录来源|Catalog source/)).not.toBeInTheDocument()`。
- `ui/src/components/settings-form.stories.test.tsx`：四条既有用例改为以目录加载完成的控件（Provider / Model 下拉或文本框）为等待锚点，并各补一条同样的负向断言。
- `.freak`：登记 `ModelCatalog.source` 在界面移除提示行后只剩契约注释，提示下次改动前决定该字段去留。
