# API 三级权限：超级管理员/管理员/普通用户

## Background

认证并入后角色只有 `user` / `admin` 两级，且仅 `POST /auth/users/{id}/ban` 用了 `require_admin`；其余业务端点只要求「已登录」，没有显式权限级别。本期落地通用经典三级权限：**超级管理员 > 管理员 > 普通用户**，并让每个端点都显式声明所处级别。

## Scope

- 角色扩展为 `super_admin` / `admin` / `user`，依赖按层级继承：super_admin 满足 admin 与 user，admin 满足 user。
- `auth/deps.py` 提供 `require_user` / `require_admin` / `require_super_admin`，并给依赖打 `__access_tier__` 标记，便于守卫测试校验。
- 全部后端端点显式分级：
  - public（无需登录）：`/health/`、`POST /auth/register|login|logout`、`GET /templates`、`GET /.well-known/resume-agent`、OpenAPI/docs。
  - user：`/auth/me`、`/auth/password`、resumes / jds / profile / settings / access / backup。
  - admin：`GET /auth/users`（用户列表）、`POST /auth/users/{id}/ban`、`POST /auth/users/{id}/unban`。
  - super_admin：`POST /auth/users/{id}/role`（提升/降级；禁止改自己、禁止移除最后一个超级管理员）。
- 新增守卫测试遍历 `app.routes`，每个非 public 路由必须能解析出 {user|admin|super_admin} 之一。
- seed 的引导账号角色改为 super_admin，并对已存在的引导账号做幂等提升。
- 前端：`AuthUser.role` 纳入 super_admin；导航角色标签与管理员分区按级别显示（admin 及以上）。
- 文档：`docs/design.md`、`ui/README.md`。

## Non-goals

- 不做「用户-角色-权限」三段式可配置 RBAC（权限表/角色表/菜单表绑定），本期为固定三级角色 + 层级继承。
- 不做模板写管理端点（后续管理端工单）。
- 不改 PAT scope 体系（外部接入的 scope 校验归后续工作）。
- 不做企业多租户（用户故事已列为暂不包含）。

## Acceptance Criteria

- [ ] `UserRole` 为三值；user 访问 admin 端点得到 403，admin 通过；super_admin 端点仅 super_admin 通过。
- [ ] 所有非 public 路由都能解析出权限级别，守卫测试枚举 `app.routes` 无遗漏。
- [ ] `GET /auth/users` 需要 admin；`POST /auth/users/{id}/role` 需要 super_admin，且不能改自己、不能移除最后一个 super_admin。
- [ ] 引导账号 seed 后角色为 super_admin；已存在的引导账号被提升。
- [ ] 前端按角色显示管理入口与角色标签，i18n zh/en 键一致。
- [ ] 后端 pytest、前端 test/build/lint、`archkit inspect .` 全部通过。
