# 定义 PRD v0.4 屏幕流与设计组件

## Background

PRD v0.2 已明确 P0 简历、Profile、JD、岗位微调、Agent 运行、开放接入、模板和设置能力，但尚未把用户故事转换为可供设计与实现使用的屏幕清单、导航结构和共享组件。仓库没有独立 UJ/FEA/PER/BR 工件，因此本工单以 PRD、US-* 用户故事和 C-01～C-13 公共契约作为可追溯证据，并明确标注推导结果。

## Scope

- 产出 `docs/prd/对话式简历编辑系统-屏幕流定义.md`。
- 定义 P0 页面、关键 Modal/Panel、导航关系、状态和设计组件。
- 建立 US/C 证据到 SCR/DES 的映射、Feature-to-Screen 矩阵和旅程覆盖检查。
- 记录 P1/EXT 的预留入口、屏幕复杂度和进入 v0.5 Red Team Review 前的未决项。

## Non-goals

- 不实现 React 页面、后端接口、数据库模型或视觉原型。
- 不替 D-01～D-05、Q-01～Q-14 做产品决策。
- 不把 P1/EXT 能力伪装成 P0 页面验收范围。

## Acceptance Criteria

- [x] 所有 P0 用户旅程步骤映射到 SCR 条目或明确记录为待决入口。
- [x] 所有 P0 功能域和公共契约边界至少映射到一个 SCR；无孤立核心能力。
- [x] 导航无死端，关键写入、确认、冲突、失败和恢复状态有承载位置。
- [x] 共享导航、工作台、Diff、状态、选择器和版本组件形成 DES 条目。
- [x] P0 页面数量控制在 15 个以内，并给出复杂度评估。
- [x] 文档引用仓库内 PRD、用户故事、公共契约和原型，`git diff --check` 与 `archkit inspect .` 通过。

## Implementation

- 新增 `docs/prd/对话式简历编辑系统-屏幕流定义.md`，把 PRD、用户故事和公共契约转换为 7 条推导旅程、17 个 P0 功能簇、12 个 Page、12 个 Modal/Panel 和 15 个 DES 组件。
- 建立 Hub & Spoke 主导航与简历编辑/JD 微调 Linear Flow，覆盖创建、编辑、Diff、确认、结算、冲突、恢复、导出、外部接入和迁移。
- 明确仓库没有正式 UJ/FEA/PER/BR 工件，使用带 `-D` 后缀的推导标识并记录替换规则；保留 D-01～D-05、Q-01 未决项。
- 以 `ui/prototypes/index.html` 作为视觉基线，补充其未覆盖的编辑、Diff、JD、Profile、冲突和导出状态边界。
