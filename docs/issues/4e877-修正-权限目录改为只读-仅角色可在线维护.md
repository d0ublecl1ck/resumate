# 修正：权限目录改为只读，仅角色可在线维护

## Background

上一期（b4440）做了权限目录的在线增删改。但权限码与端点强绑定：端点用 `require_permission("code")` 静态声明，`require_permission` 在导入期就用 `rbac.py` 目录校验；UI 新建的权限码不会被任何端点使用，且 `seed_rbac` 会把目录项的 name/group 同步回代码值。因此权限的在线增删改是**无效能力**，应改为只读；可变的是角色（自定义角色 + 从只读目录勾选权限）。

## Scope

- 移除 `permission:write` 权限与 `POST/PATCH/DELETE /auth/permissions`；保留 `GET /auth/permissions` 作为只读目录。
- 移除 `permissions.is_system`（新增迁移回退），权限目录完全由 `app/modules/auth/rbac.py` 拥有。
- 角色仍可在线维护：`POST|PATCH|DELETE /auth/roles`（`role:write`），权限从只读目录勾选；系统角色只读、在用角色不可删、code 不可变等规则不变。
- 前端 `/admin/rbac` 的权限区改为只读目录列表；移除权限新建/编辑/删除弹窗与相关 API、类型、i18n 词条。
- Storybook stories、MSW handlers、测试与 `docs/design.md` / `ui/README.md` 同步。

## Non-goals

- 不做运行时权限表驱动鉴权：端点权限仍由代码声明，权限表只作为目录。
- 不恢复权限的在线编辑。

## Acceptance Criteria

- [x] `/auth/permissions` 只有 `GET`；不存在权限的写接口与 `permission:write` 权限码。
- [x] 权限表不再有 `is_system`；目录为 20 项（移除 permission:write）。
- [x] 角色 CRUD 与全部保护规则保持；守卫测试通过（新端点均声明权限）。
- [x] 前端权限区只读，角色区仍可增删改；权限不足无入口。
- [x] 后端 pytest、前端 test/build/lint、`archkit inspect .`、`build-storybook` 通过。

## Implementation

- 移除 `permission:write` 权限码与 `POST|PATCH|DELETE /auth/permissions`；`/auth/permissions` 仅保留 `GET` 只读目录。
- 迁移 `d1e5f9a3b7c2` 删除 `permissions.is_system`（权限全部由代码目录拥有，不再区分系统/自定义）。
- `seed_rbac` 现在把权限表**精确镜像** `rbac.py`：补齐/更新目录项，并清理目录外的孤立权限（连带删除其 `role_permissions`），避免删除权限码后残留死数据。
- `service` / `api` / `dao` / `schemas` 移除权限 CRUD（`create/update/delete_permission`、`_get_permission_or_raise`、`PermissionCreate/PermissionUpdate`）；角色 CRUD 与全部保护规则保持不变。
- 前端 `/admin/rbac` 权限区改为只读卡片列表；移除权限新建/编辑/删除弹窗、`createPermission/updatePermission/deletePermission` API、`PermissionInput/PermissionUpdateInput` 类型与对应 i18n 词条。
- Storybook stories、MSW handlers、页面测试同步；`docs/design.md` 与 `ui/README.md` 更新。
