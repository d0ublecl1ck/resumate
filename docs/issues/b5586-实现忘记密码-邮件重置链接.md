# 实现忘记密码（邮件重置链接）

## Background

账号目前只有「登录后改密」（`POST /auth/password`），没有找回路径：忘记密码的用户既无法自助重置，也没有任何官方渠道恢复账号。这与已经落地的「邮箱验证注册」（d7b99）不对称——注册已经用一次性邮件令牌证明邮箱归属，重置密码理应复用同一套模式。

本 Issue 按 d7b99 的模式、命名与风格补齐邮箱重置链接式忘记密码：后端两个端点 + 一次性 Redis 令牌，前端 `/forgot-password` 与 `/reset-password` 两个页面，视觉严格沿用登录页既有令牌与原型 `#auth-email-verification` 设计补充。

前端遵循仓库强顺序门禁：先定稿原型 → 先做 Storybook 给用户确认 → 用户确认后才做真实页面与后端对接。本轮交付终点是后端实现 + 后端测试通过 + 原型状态补登记 + Storybook 全状态，然后停下等确认。

## Scope

**后端（`backend/app/modules/auth/`）**

- `POST /auth/password/forgot`：入参 `email`；**始终 202 中性响应**，不泄露邮箱是否存在；命中账号且不在冷却/配额内时签发一次性重置令牌并异步发信。
- `POST /auth/password/reset`：入参 `token` + `new_password`；消费一次性令牌、写入新 `password_hash`、撤销该用户全部既有会话；成功返回 204。
- 新增 `password_reset_store.py`：镜像 `verification_store.py` 的「只存 SHA-256 哈希 + TTL + 一次性消费 + 小时配额 + 冷却」，使用独立 Redis key 前缀 `auth:password_reset:` / `auth:password_reset_lookup:` / `auth:password_reset_cooldown:` / `auth:password_reset_quota:`。
- 新增机器错误码 `PASSWORD_RESET_TOKEN_INVALID`（400）与异常类 `PasswordResetTokenInvalid`，风格对齐 `VERIFICATION_TOKEN_INVALID`（含中文 message）。
- 新密码沿用 `ChangePasswordRequest` 的长度约束（8–128）；新密码与旧密码相同必须被拒绝。
- `mailer.py` 增加 `send_password_reset_email`，正文与验证邮件同风格，链接由 `settings.public_web_base_url` 构造。
- `config.py` 增加 `password_reset_token_ttl_seconds` / `password_reset_lookup_ttl_seconds` / `password_reset_resend_cooldown_seconds` / `password_reset_max_sends_per_hour`。
- 不新增数据库迁移（`users.password_hash` 已存在）。

**前端（`ui/`）**

- 新增 `/forgot-password`：输入邮箱 → 中性「已发送」提示 + 重发冷却。
- 新增 `/reset-password?token=`：新密码 + 确认密码 → 成功态 / 失效态（缺 token 视为格式不完整）。
- 登录页增加「忘记密码？」入口。
- 文案全部走 i18n，zh-CN 与 en 键结构一致，en 无残留中文；机器错误码只经键映射渲染。
- Storybook 沿用 `Pages/EmailVerification` 的组织方式，扩到 `Pages/PasswordReset`。

## Non-goals

- 不做短信 / 安全问题 / 人工申诉等非邮件找回方式。
- 不新增数据库迁移，不改 `users` 表结构。
- 不提供「按 token 重发重置邮件」入口：`password_reset_lookup` 记录只用于 `reset` 在消费令牌前解析账号（同密码校验失败时保住这条链接），失效链接页直接引导回 `/forgot-password` 重新申请。
- 不在本轮做真实页面路由接线与预置数据联调（等 Storybook 确认后另起一轮）。
- 不改动邮箱验证注册的既有对外行为。

## Acceptance Criteria

- [x] 后端：`forgot` 对未知邮箱、已知邮箱、冷却中、超配额一律 202，且不泄露邮箱是否存在。

## Implementation

**后端**

- `password_reset_store.py`（新增）：`issue_reset` / `lookup_reset` / `consume_reset` / `in_resend_cooldown` / `start_resend_cooldown` / `is_within_send_quota`，与 `verification_store.py` 一一对应。`consume_reset` 同时删除令牌与 lookup 记录，已用链接立即报失效。
- `schemas.py`：`ForgotPasswordRequest`、`PasswordResetRequest`、`PasswordResetAccepted`（线上字段 `newPassword`，与既有 camelCase 契约一致）。
- `service.py`：`forgot_password` 对未知地址、冷却中、超配额一律返回中性的 `PendingPasswordReset(email, None)`，只有真的发信时才带 link；`reset_password` 顺序为「lookup 解析账号 → 同密码校验 → 消费令牌 → 换密 → 撤销全部会话」，因此同密码被拒时链接仍可重试。
- `api.py`：两个端点；`forgot` 用 BackgroundTasks 异步发信（与 register / resend 同一写法），`reset` 返回 204。
- `errors.py` / `config.py` / `mailer.py` / `.env.example`：新增错误码、四个配置项、`send_password_reset_email` 与配置示例。
- `docs/design.md` §核心实体接口：补记两个端点。

**前端（Storybook 先行阶段）**

- `lib/resend.ts`（新增）：把 d7b99 的重发状态机抽成通用 `useResendMachine` + 统一 `authMachineErrorMessage`，验证邮件与重置邮件共用。
- `lib/verification.ts`：改为复用通用状态机，对外导出保持不变（`useVerificationResend` / `ResendState` / `verificationErrorMessage`）。
- `lib/password-reset.ts`（新增）：`usePasswordResetResend` 与 `passwordResetSubmitErrorMessage`。
- `lib/types.ts` / `lib/api.ts`：`PASSWORD_RESET_TOKEN_INVALID` 机器错误码、`PasswordResetAccepted` / `PasswordResetInput` 类型、`forgotPassword` / `resetPassword` 客户端函数。
- `i18n/locales/{zh-CN,en}/auth.ts`：新增 `passwordReset` 命名空间与 `fields.newPassword|confirmPassword`、`errors.passwordResetTokenInvalid`，两侧键结构一致。
- 组件（全部复用 `AuthShell` 与登录页既有令牌，无新视觉规则）：`forgot-password-form.tsx`、`forgot-password-sent.tsx`、`reset-password-form.tsx`、`reset-password-result.tsx`。
- `components/password-reset.stories.tsx`（新增，标题 `Pages/PasswordReset`）：21 个 story，覆盖表单、提交中、校验失败、已发送、重发 pending/冷却/网络错误、超长邮箱、禁用、重置成功、三种失效原因、令牌失配、网络错误与 StrictMode。
- `mocks/handlers.ts`：补 `/api/auth/password/forgot` 与 `/api/auth/password/reset` 的默认 MSW 契约。
