# 简历编辑器对话区接入历史会话并支持继续对话

## Background

### 现状

- 历史会话的展示组件已经完整实现：`ui/src/components/session-history.tsx` 导出 `SessionList`（列表）与 `SessionDetail`（消息流），并有 Storybook `Pages/SessionHistory`（9 个状态）与 zh-CN/en 文案；但仓库内**没有任何页面/组件引用它们**，简历编辑器的对话区（`RunPanel`）只展示当前简历 active run 对应会话的消息，用户不能切换到历史会话，也不能在历史会话继续对话。
- 会话契约（`docs/agent/agent-operation-api.md` §19.1 / §21.1）：`agent_sessions` 只绑 owner，**不含 resume_id**；`scope` 是轮次属性。`POST /sessions` 建的会话不绑定任何简历，一条会话可以横跨多份简历与主档。
- 简历 run 的会话落点：`POST /resumes/{resume_id}/runs` 接受可选 `sessionId`；带该字段时运行体以 `--session <id>` 启动，`agent-core` 的 `SessionJournal.start` 复用同一会话并把 seq 接在既有最大 seq 之后（不带时新建会话）。轮次由运行体创建，`scope=resume`、`resume_id` 为该简历，`session_id` 为所选会话。
- 消息落库入口：`POST /sessions/{id}/messages`，`seq` 由调用方分配，`(session_id, seq)` 幂等。主档助手 `ui/src/components/profile-assistant.tsx` 的发送路径即「先 append 用户消息，再起 run」，是本仓既有参考实现。

### 结论（作用域）

「切到历史会话继续对话」的正确写法是：把用户消息 `POST /sessions/{id}/messages` 追加进所选会话，再用同一 `sessionId` 起 resume run（`POST /resumes/{resume_id}/runs` 带 `sessionId`）。这样新轮次与消息都落在**同一个 session**，不会新建会话；由此产生的会话可能是「简历 + 主档混合会话」，这是 §21.1 允许的既有语义，不做额外约束。

`11ad1`（`GET /sessions?scope=profile`）服务的是主档助手挑选「主档会话」以避免 N+1 与误采；简历编辑器要列**全部**会话，不需要 scope 过滤，因此本工单**不改后端**，与 `11ad1` 不冲突。

## Scope

- `ui/src/lib/api.ts`：`startRun` 增加可选 `sessionId` 并透传到请求体（向后兼容，缺省行为不变）。
- 新增对话区「历史会话」视图组件：复用 `SessionList` / `SessionDetail`，在简历编辑器对话区提供入口；当前 active run 的会话高亮；选中后加载 `listSessionMessages`；在选中会话继续发消息（append + 带 sessionId 起 run）。
- `ui/src/i18n/locales/{zh-CN,en}/sessionHistory.ts`：补齐入口与继续对话相关键，两侧键结构一致。
- `ui/src/components/session-history.stories.tsx`（或新 story）：补充接线后的状态。
- `ui/prototypes/index.html`：SCR-003 简历编辑工作台同步历史会话入口与继续对话状态。
- 测试：MSW 断言「继续发送」命中 `POST /api/sessions/{id}/messages`（seq 递增）且 `POST /api/resumes/{id}/runs` 请求体带同一 `sessionId`。

## Non-goals

- 不改后端：不新增 `GET /sessions?scope=`、不改会话/轮次写入语义、不改数据库、不做迁移。
- 不改 `SessionList` / `SessionDetail` 的响应式展示契约与字段形状。
- 不引入会话级标题、用途或摘要字段（那是 `11ad1` 方案 B）。
- 不处理历史混合会话的展示/迁移待决点。

## Implementation

- `ui/src/lib/api.ts`：`StartRunInput` 增加可选 `sessionId`，非空时写入 `POST /resumes/{id}/runs` 请求体；缺省行为不变。
- `ui/src/components/resume-chat-panel.tsx`（新增）：对话区外壳，顶部 `role=tablist` 切换「当前对话 / 历史会话」。当前对话渲染原有 `RunPanel`；历史会话用 `listSessions()` + `SessionList`、`listSessionMessages()` + `SessionDetail`，active run 的 `conversationId` 作为高亮 `activeId`。继续发送：重读会话消息取 `max(seq)+1` → `appendSessionMessage(sid, {seq, role:"user", content:{role:"user",content:prompt}})` → `startRun(resumeId, {prompt, executionMode, sessionId: sid})`，随后轮询会话消息直到出现更新的 assistant 回复（60s 超时兜底）。
- `ui/src/components/resume-editor.tsx`：中栏由 `RunPanel` 换成 `ResumeChatPanel`。
- `ui/src/components/resume-chat-panel.test.tsx`（新增）：MSW 断言列表来自 `GET /sessions`、当前会话 `aria-current`、选中渲染 `GET /sessions/{id}/messages`、继续发送 `seq=max+1` 且 `POST /resumes/{id}/runs` body 带同一 `sessionId`、未调用 `POST /sessions`。
- `ui/src/components/resume-chat-panel.stories.tsx`（新增）：`Pages/ResumeChatHistory`，当前 Run / 历史列表 / 历史详情 3 个 story，MSW 驱动。
- `ui/src/i18n/locales/zh-CN/sessionHistory.ts` 与 `.../en/sessionHistory.ts`：新增 `currentChat` 与 `continue.{placeholder,send,hint}`，两侧键结构一致。
- `ui/prototypes/index.html`：SCR-003 简历编辑工作台同步「当前对话 / 历史会话」切换、列表高亮、继续对话语义与状态条目。

未改后端：`POST /resumes/{id}/runs` 的 `sessionId` 与 `POST /sessions/{id}/messages` 均为既有契约（`backend/app/modules/agent/schemas.py`）。
