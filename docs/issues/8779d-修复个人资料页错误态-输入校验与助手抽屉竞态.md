# 修复个人资料页错误态-输入校验与助手抽屉竞态

## Background

三份独立测试报告在 `/profile`（SCR-004）命中同一组缺陷，其中多数是「服务端失败被前端静默」的同类问题：

1. `GET /profile` 非 2xx 时 `ui/src/pages/profile.tsx:11` 只判 `isPending || !profile`，react-query 重试耗尽后仍永久渲染「加载中」，用户看不到错误也无法重试。
2. 主档保存失败静默：`ui/src/components/profile-basics-form.tsx:32-50` 只有 `try/finally` 没有 `catch`；`ui/src/components/profile-workspace.tsx:56-60` 未捕获，于是产生 unhandled rejection 且页面无任何错误文案。
3. 邮箱无格式校验：`profile-basics-form.tsx:30` 的 `valid` 只看 `fullName`，`ZZ-TEST-not-an-email` 能保存成功并持久化。
4. 缺 `maxLength` 与断行：主档「一句话头衔」240 个 `W` 使 `document.scrollWidth` 从 1440 涨到 3471；事实内容 5000 连续字符涨到 38805。
5. 事实标题 >200 字符：前端无 `maxLength`；后端 `backend/app/modules/profile/schemas.py:26-33` 的 `title: str` 无 `max_length`；DB 列是 `String(200)`（`models.py:30`），Postgres 报错被兜成 500，前端静默。阈值实测 200 OK / 201 起 500。
6. 「对话维护资料」抽屉不是真模态：`ui/src/components/profile-assistant.tsx:262` 手写 `fixed inset-0 role=dialog`，打开后焦点仍在触发按钮、Tab 走到背景控件、Esc 不关闭（三份报告同时命中）。
7. 助手回复实时不显示：`profile-assistant.tsx:173-192` 只处理 SSE `turn.updated`、没有处理 `snapshot`；轮询发现新轮次后只 `setAwaitingTurn(false)`，不补拉会话消息，于是要关闭重开或刷新才看到后端已写入的 `{"role":"assistant","content":"收到"}`。
8. 无权限/服务端错误被误判为「模型未配置」：`ui/src/components/agent-onboarding.tsx:76-82` 的 `agentAvailabilityFromModelConfig` 用 `modelQuery.data ?? {keyConfigured:false}`，把 `undefined`（加载失败/无权限）当归零。
9. 同一 tick 同步两次 click 落两条重复事实：`profile-fact-form.tsx:41-63` 的 `busy` 是异步 state，第二次 click 读到的仍是 `false`。
10. `GET /api/models/config` 500 重试期间抽屉正文渲染 `null`，约 10s 空白。
11. 抽屉遮罩与右上 X 的 `aria-label` 都是 `common.actions.close`（「关闭」），辅助技术无法区分。
12. `ui/src/lib/profile.ts:7` 的 `FACT_TYPE_ORDER` 与 `profile-workspace.tsx:18-25` 的 `SECTIONS` 顺序不一致（education/skill 互换），两处会继续漂移。

## Scope

- `ui/src/pages/profile.tsx`：查询 `isError` 时渲染 `StateBlock kind="error"`（错误码）与重试，照搬 `ui/src/pages/settings.tsx:27-36`。
- `ui/src/components/profile-basics-form.tsx`：`catch` 保存失败并给出可读错误与重试；邮箱格式校验（`aria-invalid` + 可见提示）；输入侧 `maxLength`。
- `ui/src/components/profile-workspace.tsx`：展示侧对用户内容加断行（`break-words` / `overflowWrap: "anywhere"`），卡片 `overflow-hidden`；统一 `SECTIONS` 与 `FACT_TYPE_ORDER` 的单一来源。
- `ui/src/components/profile-fact-form.tsx`：标题 `maxLength=200` 与超限提示；同步提交守卫；422 message 展示。
- `ui/src/components/profile-assistant.tsx`：改用 `ui/src/components/ui/modal.tsx` 原语；处理 SSE `snapshot`；新轮次出现时补拉会话消息；加载中骨架；区分可用性四态。
- `ui/src/components/agent-onboarding.tsx`：新增「加载失败（可重试）」「无权限」两态，两种都不引导去设置页。
- `backend/app/modules/profile/schemas.py`：`ProfileFactCreate.title` 与 `ProfileFactUpdate.title` 加 `max_length=200`，超限走既有 `RequestValidationError` → 422 `VALIDATION_FAILED` 约定（不要 500）。
- `ui/src/i18n/locales/{zh-CN,en}/profile.ts` 与 `agentOnboarding.ts`：同步新增/修改词条，键结构一致。
- `ui/prototypes/index.html`：`screen-profile` 补登可见状态（错误块 / 校验提示 / 骨架 / 抽屉模态契约）。
- 测试：`ui/src/pages/profile.test.tsx`（新增）、`ui/src/components/profile-workspace.test.tsx`、`ui/src/components/profile-assistant.test.tsx`、`ui/src/components/agent-onboarding.test.ts`、`backend/tests/test_profile.py`。

## Non-goals

- 不改数据库模型与 DB 列（`String(200)` 已存在，无需迁移）。
- 不改 `/settings`、`/settings/access`、`/settings/backup` 与「生成简历」弹窗（另一批并行工作）。
- 不新增事实的 UI 删除/归档入口、搜索与筛选（产品未要求）。
- 不改别的后端模块行为；不动 `jd-ai-parse` worktree。

## Acceptance Criteria

- [ ] `GET /profile` 500：渲染错误块（错误码 + 重试），不再无限 Loading；点重试重新发 `GET /profile`。
- [ ] `PATCH /profile/basics` 500：行内可见可读错误且可重试，`window` 无 unhandled rejection。
- [ ] 邮箱 `ZZ-TEST-not-an-email`：前端拦住（`aria-invalid` + 可见提示），不发 `PATCH`。
- [ ] 超长无空格头衔与事实内容：`document.scrollWidth === clientWidth`，卡片不横向溢出。
- [ ] 事实标题 201 字符：前端 `maxLength` 拦住；绕过前端直连后端返回 422 `VALIDATION_FAILED` 且界面显示 message，绝不 500。
- [ ] 抽屉：焦点入内 / Tab 不逃逸 / Esc 关闭 / 关闭后焦点归还触发按钮 / 背景 inert，保留 `role=dialog`、`aria-modal`、`aria-label`。
- [ ] 抽屉发消息后轮次结束能在同一会话实时看到助手回复（`snapshot` 与轮询两条路径都补拉消息），重复 3 次不偶发。
- [ ] `GET /api/models/config` 403/500 显示「加载失败可重试」/「无权限」，不显示「先把助手开起来」也不给「去设置」；加载中显示骨架而非空白。
- [ ] 同一 tick 同步两次 click 只落一条事实。
- [ ] 遮罩与右上 X 的 `aria-label` 不同。
- [ ] `FACT_TYPE_ORDER` 与 `SECTIONS` 顺序同源。
- [ ] `pnpm -C ui test`、`pnpm -C ui build`、`cd backend && uv run pytest -q`、`archkit inspect .` 全绿。

## Implementation

- `ui/src/pages/profile.tsx`：`GET /profile` 非 2xx 时渲染 `StateBlock kind="error"`（错误码 + 重试），重试走 react-query `refetch`，不再永久「加载中」。
- `ui/src/components/profile-basics-form.tsx`：`catch` 保存失败 → 行内 `role=alert`（可读文案 + 错误码 + 重试）；邮箱正则兜底校验（`aria-invalid` + `aria-describedby` + 可见提示，非法时不发 PATCH）；全部输入加 `maxLength`。
- `ui/src/lib/api-error-text.ts`（新增）：只有 422 `VALIDATION_FAILED` 才展示后端 message，其余错误码回落 i18n 文案，避免英文原文泄漏到界面。
- `ui/src/components/profile-fact-form.tsx`：标题 `maxLength=200` + 超限本地守卫（与后端 `max_length=200` 对齐）；`submittingRef` 同步守卫同一 tick 双 click；`catch` 后就地展示错误，422 message 直出。
- `ui/src/components/profile-workspace.tsx`：`SECTIONS` 改为从 `FACT_TYPE_ORDER` 派生（分区与类型下拉单一顺序来源）；主档头衔与事实标题 / 内容加 `.wrap-anywhere`，事实卡片 `overflow-hidden`。
- `ui/src/index.css`：新增 `.wrap-anywhere { overflow-wrap: anywhere; word-break: break-word; }`。
- `ui/src/components/ui/modal.tsx`：扩展可选 `placement="right"`（右侧抽屉）与 `closeLabel`，Popup 显式补 `role="dialog"` / `aria-modal="true"`；既有居中弹窗行为不变。
- `ui/src/components/profile-assistant.tsx`：手写 `fixed inset-0 role=dialog` 改为 `Modal` 原语；SSE 同时处理 `snapshot` 与 `turn.updated`；轮次集合变化（轮询发现新轮次）时补拉会话消息；可用性六态（加载骨架 / 读取失败可重试 / 无权限 / 未配置 / 运行体离线 / 可用）。
- `ui/src/components/agent-onboarding.tsx`：新增 `agentAvailability()` 六态判定；`load_failed` 给「重试」，`forbidden` 不给按钮，两者都不引导去设置页。
- `ui/src/i18n/locales/{zh-CN,en}/profile.ts`、`agentOnboarding.ts`：同步新增 / 修改词条，键结构一致。
- `ui/prototypes/index.html`：`#screen-profile` 的 `states` 补登错误块 / 邮箱校验 / 超长断行 / 标题上限 / 抽屉模态契约 / 可用性六态 / 实时回复等可见状态。
- `backend/app/modules/profile/schemas.py`：`ProfileFactCreate.title` 与 `ProfileFactUpdate.title` 加 `max_length=200`，超限走既有 `RequestValidationError` → 422 `VALIDATION_FAILED`（message「请求参数校验失败：title」），不再落到 DB 变 500。
- `README.md`：同步测试统计口径（后端 251 → 254，前端 42 files / 306 → 43 files / 329）。
