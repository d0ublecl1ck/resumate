# 修复简历编辑器对话链路：会话连续性与审批后页面刷新

## Background

用户在本机 dev 环境实测 `http://localhost:5173/resumes/res_4f159c4f2248` 的对话 / Run 面板，报告两个稳定复现的问题，已用代码与数据库证据定位到根因。

会话每轮新建的根因与证据：`ui/src/lib/api.ts` 的 `startRun` 只发送 `{prompt, executionMode}`，从不带 `sessionId`；后端 `backend/app/modules/agent/schemas.py` 的 `RunStartRequest` 与 `runner.start_run` 已支持可选 `session_id`。实测数据：res_4f159c4f2248 在 2026-10-08 20:54:13 / 20:54:27 / 20:55:35 三次发送各建了一个会话（sess_c022485d9d37 / sess_68eb3d49531e / sess_c4b660488fd7），而 `getActiveRun` 只读「最新一轮的 sessionId」的消息，因此面板只显示当前一轮，上一轮对话消失。

审批后页面不更新的根因与证据：`ui/src/components/run-panel.tsx` 的 approve / reject mutation 只 invalidate `["active-run", resumeId]`，不刷新 `["resume", id]`；`ui/src/components/resume-editor.tsx` 的 `doc` 是 `useState(resume.draft ?? resume.document)`，只在挂载时取一次，没有随 `resume` prop 变化的同步逻辑。批准后服务端工作副本已经改变，编辑器仍显示旧内容与旧保存状态。用户口径：「批准之后，授权改了，页面没更新」。

## Scope

- 让同一份简历的连续多轮对话落在同一个会话：`startRun` 支持并透传 `sessionId`（取当前展示轮次的会话），运行体续用该会话。
- 让对话面板在本简历的轮次 / 会话已经被切成多条时仍按时间显示完整对话历史，而不是只显示最新一轮。
- 审批（批准 / 拒绝）成功后刷新简历数据，并让编辑器在服务端工作副本变化后同步本地文档与保存状态；本地存在未保存输入时不得静默覆盖用户输入。
- 实测报告确认的其它对话缺陷，按同一修复批次纳入或显式后置。

## Non-goals

- 不改 agent-core 的会话 seq / checkpoint 语义。
- 不新增「会话用途」或 `GET /sessions?scope=` 契约（该方向见 backlog 11ad1）。
- 不做历史数据迁移：修复前已经切分的旧会话不合并写回数据库。

## Acceptance Criteria

- [x] 同一简历连续发送两条消息，第二次请求体带 `sessionId`，`agent_session_messages` 里两条用户消息属于同一 `session_id`，且第二轮面板仍显示第一轮对话。
- [x] 面板按时间显示该简历多个历史轮次的对话（含修复前已切分的历史会话），同一条用户消息不重复渲染。
- [x] 批准待办后编辑器显示的工作副本内容与保存状态刷新为服务端最新值；拒绝同样刷新。
- [x] 本地存在未保存输入时，审批后的刷新不静默覆盖用户输入，行为有测试断言。
- [x] `pnpm -C ui test` 通过；`archkit inspect .` 通过。

## Implementation

- 会话连续性：`ui/src/lib/api.ts` 的 `StartRunInput` 增加 `sessionId` 并写进请求体；`AgentRun.sessionId` 由 `mapTurnToRun` 透传（`ui/src/lib/types.ts`）；`ui/src/components/run-panel.tsx` 发送时带上当前展示轮次的会话。后端 `RunStartRequest.session_id` 与 agent-core `--session` 原本就支持，未改契约。
- 历史聚合：`getActiveRun` 不再只读最新一轮的会话，而是把该简历所有轮次的会话消息并成一条按时间排序的时间线（同刻用 `seq` 兜底），并把未决待办（`rejected` / `consumed` 除外）跨轮次合并；某个会话读不到时静默跳过，不阻塞当前轮次。修复前已经切分的旧会话因此重新出现在面板里。
- 审批后刷新：`RunPanel` 在审批成功时、以及轮次状态或待办状态发生变化时失效 `["resume", resumeId]` 与 `["resumes"]`。批准只是授权，真正的写入发生在之后的 `patches:apply`，所以按状态变化触发而不是只按点击时机触发；`ui/src/components/resume-editor.tsx` 用服务端签名（id + currentVersionId + saveState）同步 `doc` 与 `saveState`，本地不存在未保存内容时同步、dirty 时不覆盖用户输入。
- 回复语言：`agent-core/src/resumate_agent_core/runtime.py` 的 `bound_system_prompt` 对所有 scope 追加语言指令（按用户最新消息的语言回复），简历绑定段只对 resume scope 生效。
