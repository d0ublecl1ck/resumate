# 凭据与账号生命周期：改密码与封号即时失效

## Background

仅有登录会话还不够：改密码与封号必须立即让已有会话失效，否则被撤销的凭据仍可继续访问。

## Scope

- `POST /auth/password`：校验当前密码，更新哈希，撤销该用户全部 Redis 会话并清 Cookie。
- `POST /auth/users/{user_id}/ban`：仅管理员；写入 `is_banned`/`banned_at`/`banned_reason`，撤销该用户全部会话；禁止封禁自己。
- 扩充机器错误码：`UNAUTHENTICATED`、`INVALID_CREDENTIALS`、`ACCOUNT_BANNED`、`FORBIDDEN`、`EMAIL_ALREADY_REGISTERED`。
- 测试：登出即时失效、改密码后旧会话 401 且旧密码不可登录、封号后目标会话 401 且登录被拒、非管理员封号 403。

## Non-goals

- 解封、封禁审计日志、通知与申诉流程。
- 会话列表、单设备撤销与滑动续期。

## Acceptance Criteria

- [ ] `POST /auth/password` 校验当前密码，成功后该用户全部会话立即失效。
- [ ] 改密码后旧密码登录失败、新密码可登录。
- [ ] 封号仅管理员可执行；封禁后目标用户全部会话立即失效，登录返回 `ACCOUNT_BANNED`。
- [ ] 管理员不能封禁自己。
- [ ] `uv run --directory backend pytest` 与 `archkit inspect .` 通过。
