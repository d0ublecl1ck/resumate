# 简历库页面缺陷修复与筛选状态深链

## Background

对 `/resumes`（SCR-002 简历库）做无头浏览器实测后确认的缺陷：页面主体功能可用，但简历生命周期操作未接线、筛选状态不可深链，且若干文案与错误归类与实现语义不符。

已确认的现象与源码位置：

- 卡片右下角「归档」/「恢复」按钮没有任何 `onClick`（`ui/src/components/resume-library.tsx`），`ui/src/lib/api.ts` 也没有对应函数；后端 `POST /resumes/{id}/archive` 与 `POST /resumes/{id}/restore` 已存在且可用（`backend/app/modules/resume/api.py`），属纯前端未接线。
- Tab、搜索词、标签筛选只存在组件 `useState` 中，刷新即丢失；`?create=1` 关闭弹窗后仍留在地址栏，刷新会再次自动弹出。
- 搜索用 `String.includes` 直接比较，区分大小写（`qa` 搜不到标题含 `QA` 的简历）。
- 标签 chips 由全量简历计算，切到「归档」Tab 后仍展示只存在于活跃简历的标签，点击必然落到 0 命中空态。
- `targetRole` 为空时卡片仍渲染「岗位方向：」，冒号后无内容。
- 「归档」Tab 空态复用活跃态描述「点击右上角新建一份简历开始。」，与当前 Tab 语义矛盾。
- 复制流程第二步的选择弹层 `ui/src/components/resume-picker-dialog.tsx` 自绘遮罩与容器，未使用 `ui/src/components/ui/modal.tsx` 原语，因此没有 Esc 关闭、焦点陷阱与背景 `inert`。
- `ui/src/lib/api-client.ts` 对非 JSON 的错误响应把机器错误码缺省为 `VALIDATION_FAILED`，导致 `text/html` 的 500 被显示成「创建参数不合法」。

## Scope

- 归档 / 恢复接线：`ui/src/lib/api.ts` 增加 `archiveResume` / `restoreResume`；`resume-library.tsx` 卡片按钮接上回调，成功后失效 `resumes` 与 `workbench-summary` 查询，失败按既有错误映射显示可读提示。
- 筛选状态入 URL：Tab、搜索词、标签写入 `/resumes` 的查询参数，刷新与深链保持；关闭创建弹窗时移除 `create=1`。
- 搜索大小写不敏感（标题与目标岗位一致对待）。
- 标签 chips 只统计当前 Tab 数据的标签集合。
- `targetRole` 为空时不渲染该行。
- 「归档」Tab 空态描述与活跃态区分，zh-CN 与 en 词条同步新增并保持键结构一致。
- `resume-picker-dialog.tsx` 改用 `ui/components/ui/modal.tsx` 原语，获得 Esc 关闭、焦点陷阱、背景 `inert`。
- `api-client.ts`：非 JSON 的非 2xx 响应不再一律归为 `VALIDATION_FAILED`，5xx 归为服务端错误；JSON 错误体的既有映射不变。
- 同步更新定稿原型 `ui/prototypes/index.html` 对应状态。

## Non-goals

- 不修改后端接口与数据模型：归档 / 恢复端点已存在且行为正确。
- 不新增简历导出、岗位匹配等未实现能力。
- 不处理未登录访问受保护路由时 `/api/auth/me` 的开发态双发：React StrictMode 下组件双挂载属预期行为，生产构建不双发；浏览器对 401 响应的控制台日志也无法由应用屏蔽。

## Acceptance Criteria

- [x] 点击卡片「归档」调用 `POST /resumes/{id}/archive`，卡片移出活跃 Tab、出现在归档 Tab；「恢复」调用 `POST /resumes/{id}/restore` 并反向生效；失败时页面出现可读的中文错误，且不静默失败。
- [x] `/resumes?tab=archived&q=<词>&tag=<标签>` 可直接打开并保持筛选；刷新后 Tab 与筛选不丢失；关闭创建弹窗后 `create=1` 从 URL 移除。
- [x] 搜索 `qa` 能命中标题含 `QA` 的简历。
- [x] 切到「归档」Tab 时，标签 chips 只包含归档简历出现过的标签。
- [x] `targetRole` 为空的卡片不出现「岗位方向：」空行。
- [x] 「归档」Tab 空态描述与活跃态不同且语义正确，zh-CN / en 键结构一致。
- [x] 复制选择层按 Esc 可关闭，焦点锁定在弹层内，背景对辅助技术不可达。
- [x] `POST /resumes` 返回非 JSON 的 500 时，界面提示为服务端失败，而不是「创建参数不合法」。
- [x] `ui/prototypes/index.html` 与 `ui/src` 实现保持一致。
- [x] `pnpm -C ui test`、`pnpm -C ui build-storybook`、`archkit inspect .` 全部通过。

## Implementation

- `ui/src/lib/api.ts`：新增 `archiveResume(id)` / `restoreResume(id)`，分别打 `POST /resumes/{id}/archive|restore`。
- `ui/src/components/resume-library.tsx`：`tab` / `q` / `tag` / `create` 统一由 `useSearchParams` 承载；卡片归档 / 恢复按钮接线（请求期间 `disabled` + `aria-busy`，成功后失效 `resumes` 与 `workbench-summary`）；搜索大小写不敏感；标签 chips 只统计当前 Tab；`targetRole` 去空白后为空则不渲染该行；归档空态用归档专用描述；归档徽标加 `whitespace-nowrap`。
- `ui/src/lib/resume-lifecycle.ts`（新增）：归档 / 恢复的错误文案映射。与创建流程的 `lib/resume-create.ts` 分开，避免把归档失败说成「创建失败」。
- `ui/src/components/resume-picker-dialog.tsx`：改用 `ui/components/ui/modal.tsx` 原语，删除手写遮罩与 `aria-modal`，拿到 Esc 关闭、焦点陷阱与背景 `inert`。
- `ui/src/lib/api-client.ts`：响应体非 JSON 且为 5xx 时归为客户端合成码 `SERVER_ERROR`；JSON 错误体与 4xx 的既有映射不变。
- `ui/src/i18n/locales/{zh-CN,en}/resume.ts`：新增 `library.empty.archivedDescription` 与 `library.errors.*`，两侧键结构一致。
- `ui/src/mocks/handlers.ts`：新增 archive / restore handlers 与 lifecycle 覆盖表，Storybook 与测试共用。
- `ui/prototypes/index.html`：同步归档有卡、归档空态、空 `targetRole`、chips 随 Tab、筛选空态与深链状态。
- 测试：`ui/src/lib/resume-lifecycle.test.ts`（新增）、`resume-library.test.tsx`、`lib/api.test.ts`、`create-resume-modal.test.tsx`、`resume-picker-dialog.test.tsx`、`pages/resumes.stories.test.tsx`、`pages/resumes.prototype.test.ts`。
