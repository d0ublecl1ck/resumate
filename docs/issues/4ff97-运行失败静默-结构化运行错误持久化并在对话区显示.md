# 运行失败静默：结构化运行错误持久化并在对话区显示

## Background

用户在 `/profile` 右侧「个人资料助手」发送「我叫黄鹏星 20050303」后界面毫无反应。真实运行日志
`backend/var/agent-runs/run_cb5380b2d04f.log` 记录了终态错误：

```
{"type":"error","code":"MODEL_ERROR","message":"model provider returned HTTP 401: Authentication Fails, Your api key: ****be21 is invalid (request_id: ...)"}
```

请求轨迹为 `POST /sessions/{id}/messages` 201 → `POST /sessions/{id}/runs` 202 → `POST /turns` 201 →
`PUT /turns/{id}/state` 200 → `POST /turns/{id}/cancel` 200。运行体在 `runtime._abort()` 里先写
`phase=failed` 的 checkpoint，再用 `reason="runtime aborted: MODEL_ERROR"` 调用 cancel；错误正文只存在于
子进程 stdout 日志和 `ErrorEvent` 事件流里，**没有任何一步把它写进可查询的轮次字段**。

后端 `UserTurnResponse` 只有 `state/result/pendingActions`：cancel 之后轮次投影是
`state=cancelled`、`result.state=cancelled`、`result_message="runtime aborted: MODEL_ERROR"`，
前端 `mapTurnToRun` 把它统一映射成 `turn_closed`，于是「失败」和「用户主动取消」长得一模一样，
用户只能看到「没反应」。运行体已经把「哪把 key 无效」写在事件里，但这条信息完全没到达界面。

## Scope

- agent-core：`runtime._abort()` 在调用 `session.cancel()` 时携带结构化错误（code/message/detail），
  cancel 请求体透传到后端；覆盖 MODEL_ERROR / BUDGET_EXCEEDED / max_turns exhausted。
- 后端持久化：`agent_turns` 新增可查询的 `run_error` JSON 列与 `run_id` 列（Alembic 迁移），
  cancel 服务在结算 cancelled 之前先落错误；`UserTurnResponse` 暴露 `runError`，SSE snapshot 与轮询同一份投影。
- 后端归一化与脱敏：统一分类（鉴权失败 / 网络超时 / 额度或预算不足 / 审批冲突 / 运行体异常）并补齐
  provider、model、已掩码 key 尾号；写库前做一次脱敏，完整 key / Authorization 头 / 堆栈一律不落库。
- 后端兜底：supervisor 在子进程非零退出或超时时，按 `run_id` 找到仍未结算的轮次，落 RUNNER_EXIT /
  TIMEOUT 错误，覆盖「进程异常退出」这条没有 ErrorEvent 的路径。
- 前端：新增共享错误块组件，简历编辑器对话区（run-panel.tsx）与个人资料助手（profile-assistant.tsx）
  共用；文案走 i18n（zh-CN / en 同结构），提供「去设置更新 Key」入口与重试。
- Storybook：为鉴权失败 / 超时 / 预算不足补错误态 story。

## Non-goals

- 不改模型 provider / agent-core 的重试与预算算法，只把已有终态错误透出来。
- 不做自动重试：重试是用户在错误块上显式点的入口。
- 不改 `ui/prototypes/index.html`、`ui/src/i18n/locales/*/profile.ts`、
  `ui/src/components/profile-assistant-panel.*`（并发子代理占用）。
- 不把运行体的完整上游响应体落库或回显：只保留可判定的单行 message。

## Acceptance Criteria

- [x] 任意 run 失败都会在界面上出现明确错误块，不再静默变成 turn_closed。
- [x] 错误块含失败类别、provider、model、已掩码 key 尾号（例：`****be21`）与「去设置更新 Key」入口。
- [x] 后端持久化结构化 `runError`，API 响应只出现掩码尾号；完整 key / Authorization / 堆栈不出现在响应、日志用户可见字段与界面。
- [x] 用真实无效 key 复现时展示「模型鉴权失败 + deepseek/deepseek-flash + ****be21」（尾号 be21 的 key 见复现口径修正）。
- [x] 前端错误块有正向（期望文案）与负向（禁止出现完整 key）断言；后端同样双向断言。
- [x] `cd backend && .venv/bin/python -m pytest -q`、`pnpm -C ui test`、`pnpm -C ui exec tsc -b --noEmit`、

## Implementation

链路：运行体 runtime._abort() → TurnSession.report_error() → POST /turns/{id}/run-errors → service.report_run_error() →
run_errors.build_run_error()（分类 + 脱敏 + provider/model/key 尾号）→ agent_turns.run_error（JSON）→
GET /turns/{id} 与 GET /turns/{id}/events 的 UserTurnResponse.runError → 前端 mapTurnToRun →
共享 RunErrorBlock（run-panel.tsx 与 profile-assistant.tsx）。

- 后端
  - 新增 app/modules/agent/run_errors.py：机器码 + 上游文案分类（auth/timeout/quota/runner/approval/unknown）、
    key 尾号提取与掩码、Authorization/Bearer/sk-* 与堆栈行清洗、首写胜出。
  - agent_turns 新增 run_error(JSON, nullable) 与 run_id(String(64), nullable, index)；迁移
    2a17c2e1d3d3_add_agent_turn_run_error.py（batch 模式，SQLite 回归测试同样可跑）。
  - 新端点 POST /turns/{turn_id}/run-errors（run token 白名单同步放行）；cancel_turn 不清 run_error。
  - UserTurnResponse.runError 暴露给轮询与 SSE；record_run_failure(run_id, ...) 供 supervisor 按 run_id
    兜底标记超时/异常退出且仍 open 的轮次，runner._settle_child_failure 在 reap 后调用。
- agent-core
  - ResumateClient.report_run_error / TurnSession.report_error；runtime._abort 在 cancel 前上报，
    CANCELLED（用户主动取消）除外。
  - redaction.py + _RedactingProvider：provider 异常文案在进入事件流与上报前抹掉完整 key 与凭证头。
- 前端
  - RunError 类型；mapTurnToRun 把 turn.runError 映射为 AgentRun.error。
  - components/kit/run-error.tsx 共享错误块：类别、provider/model、尾号、上游信息、去设置更新 Key、重试；
    run-panel.tsx 与 profile-assistant.tsx 共用同一份实现。
  - i18n workbench.run.runError.*（zh-CN/en 同结构）；Storybook 三个错误态 story。

取舍：
- 失败存独立 JSON 列而不是塞进 run_state：run_state 是运行体 checkpoint（受 stateVersion 乐观锁约束），
  失败必须在 cancel 之后仍可查询，且不能被后续 checkpoint 覆盖。
- 用独立 run-errors 端点而不是扩展 cancel body：避免改动 cancel 的幂等键与请求哈希契约。
- 首写胜出：更具体的运行时错误不会被后到的 RUNNER_EXIT 之类更宽泛兜底覆盖。
- 只允许已掩码尾号这一种凭证形式落库/回显；完整 key、Authorization、堆栈在写库前统一清洗。
