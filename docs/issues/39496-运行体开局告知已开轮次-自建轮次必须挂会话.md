# 运行体开局告知已开轮次，自建轮次必须挂会话

## Background

标准 run 的 `AgentRuntime.run()` 会先 `TurnSession.begin()` 建一个轮次（`runtime.py:518-532`），但开局 system prompt 仍写 `Work inside one turn: open it`（`DEFAULT_SYSTEM_PROMPT`），从不告诉模型轮次已经开好了。真实 E2E（`res_aeba1b686aa4`，2026-10-07 18:43）里模型因此又调了一次 `create_turn`：

```text
turn_28a2ca1958d8  finalized   ""                          sess_bf62caea862e  ← 运行体自动开的轮次，被自动结算
turn_ad6fdeffc2da  open        "Change headline to ..."     null               ← 模型自己开的轮次，正在处理
```

两个后果：① 每个 run 白开一个轮次再被 `轮次自动结算`，产生噪音与额外写；② 模型自建轮次的 `sessionId` 是 null（resume 作用域的 `create_turn` 工具既没有 `session_id` 参数，handler 也不传），而对话正文全在运行体的会话 `sess_bf62caea862e` 里，UI 的 `getActiveRun` 只会去读「被选中轮次的 sessionId」，于是看不到用户 prompt 与 Agent 回复。

## Scope

- `agent-core/src/resumate_agent_core/runtime.py`：
  - `bound_system_prompt` / `opening_messages` 增加 `turn_id`；resume 作用域且已有轮次时明确写出「轮次已开（id）、复用它 stage/close、不要调 create_turn」。
  - `run()` 传 `session.turn_id`，`resume()` 的兜底上下文传 `turn.id`。
- `agent-core/src/resumate_agent_core/tools.py`：resume 作用域 `create_turn` 增加 `session_id` 属性并列入 required，handler 透传；运行时 `_invoke` 已有 `session_id` 注入逻辑，可确定性兜底。
- 测试：`agent-core/tests/test_runtime.py`（开局上下文含已开轮次 id 且禁止重复开轮；模型自建轮次的 POST body 带 sessionId）、`agent-core/tests/test_tools.py`（resume create_turn 的 session_id 进入 required；handler 透传 sessionId）。

## Non-goals

- 不改后端「新建轮次自动结算旧轮次」的语义。
- 不改 profile 作用域的 `create_turn`（已是 session 必填）。
- 不做「列出我的简历」或跨 scope 能力。

## Acceptance Criteria

- [ ] resume 作用域的开局 system prompt 含已开轮次 id，并明确禁止 `create_turn`。
- [ ] resume 作用域 `create_turn` 的 `session_id` 在 required 中，handler 把 `sessionId` 传给 `POST /resumes/{id}/turns`。
- [ ] 运行体用 `SessionJournal` 时，模型自建轮次的 POST body 带 `sessionId`。
- [ ] `agent-core/tests` 全绿（Red→Green）。
- [ ] 重装 uv tool 后重跑真实 UI E2E：面板能看到用户消息与 Agent 回复，且不再出现重复开轮。

## Implementation

- `agent-core/src/resumate_agent_core/runtime.py`：`bound_system_prompt` / `opening_messages` 增加 `turn_id`；resume 作用域且已有轮次时追加「An editing turn is already open (turn_id) ... do not call create_turn」，再追加原有 resume 绑定行。`run()` 传 `session.turn_id`，`resume()` 的兜底 system 上下文传 `turn.id`。
- `agent-core/src/resumate_agent_core/tools.py`：resume 作用域 `create_turn` 增加 `session_id`（required），`_create_turn` 透传给 `client.create_turn(session_id=...)`；`_invoke` 既有的 session_id 注入因此对模型自建轮次生效。
- 测试：`test_runtime.py` 新增 2 条（绑定 prompt 复用 turn_id、开局上下文含 turn_1 与 create_turn 禁令）；`test_session_journal.py` 新增 1 条（模型自建轮次的两次 POST body 都带同一 sessionId）；`test_tools.py` 新增 2 条（session_id 进 required、handler 透传 sessionId）。
