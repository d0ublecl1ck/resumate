# 简历编辑器对话区接上 AI 可用性引导与运行错误块

## Background

AI 是平台最重要的能力，助手不可用时对话区必须就地给出引导与跳转，而不是留一个仍可提交的输入框。

现状：

- `ui/src/components/agent-onboarding.tsx` 已提供 `AgentAvailabilityNotice` 与七态 `agentAvailability`（`checking` / `load_failed` / `forbidden` / `model_missing` / `auth_failed` / `runtime_offline` / `available`），`auth_failed` 只透出上游已掩码尾号（如 `****be21`），动作经 `agentAvailabilityActionEffect` 归一。
- 已关闭的 05fa6 只做到 Storybook 覆盖三个表面的四态渲染，简历编辑器对话区（`resume-chat-panel.tsx` / `run-panel.tsx`）没有真实接线：`model_missing` / `auth_failed` / `runtime_offline` 下输入框仍可提交。
- 运行失败错误块 `RunErrorBlock`（issue 4ff97）已在 `run-panel.tsx` 渲染，但没有定义它与可用性引导同时出现时的优先级。

用户已确认 Storybook 设计，本轮做真实接线。

## Scope

- `ui/src/components/resume-chat-panel.tsx`：查询 `GET /models/config` 与 `GET /agent/runtime`，用 `agentAvailability` 派生状态；把状态透传给 `RunPanel`；历史会话的「继续对话」输入同样按可用性拦截；引导动作经 `agentAvailabilityActionEffect` 分流（`settings` 去设置页、`retry` 重试两路查询）。
- `ui/src/components/run-panel.tsx`：新增可选入参 `availability` / `credentialHint` / `onAvailabilityAction`（默认 `available`，保持既有直接调用不变）；不可用时用 `AgentAvailabilityNotice` 取代输入区并隐藏发送，且不渲染 `RunErrorBlock`（同一时刻只显示一种最相关提示）。
- `ui/src/components/run-panel.test.tsx`、`ui/src/components/resume-chat-panel.test.tsx`：四态渲染、放行 / 拦截、引导与错误块不叠加、负向断言。
- `ui/src/components/resume-chat-panel.stories.tsx`：补四态真实组件 story。
- `ui/prototypes/index.html`「简历编辑器对话区」区块：补一条「引导与运行失败错误块不叠加」的规则说明。
- i18n 复用既有 `agentOnboarding` 命名空间，不新增文案键。

## Non-goals

- 不改 `agent-onboarding.tsx` 的七态派生、文案与掩码逻辑。
- 不改 `backend/**`，不新增后端契约。
- 不为 `available` 态渲染引导（保持正常放行）。
- 不新增第二个引导组件，不引入新的视觉规则。

## Acceptance Criteria

- [x] `resume-chat-panel` 在 `model_missing` / `auth_failed` / `runtime_offline` 下就地渲染 `AgentAvailabilityNotice`（panel 档），并隐藏「当前对话」与「历史会话」两处输入框与发送按钮。
- [x] `auth_failed` 显示分类文案、provider/model 对应的掩码尾号与「去更新 Key」；DOM 不得出现完整 key、`Authorization`、`Traceback`。
- [x] `runtime_offline` 说明运行体不可用；`load_failed` 给重试入口，经 action effect 触发两路查询重试。
- [x] `available` 正常放行：不显示引导，输入框与发送按钮可见。
- [x] 同一时刻只显示一种提示：不可用时 `RunErrorBlock` 不渲染，可用时运行失败错误块照常可见。
- [x] `RunPanel` 默认 `availability="available"`，既有直接调用与回归测试不变。
- [x] Storybook 四态 story 存在；给出 story id 与直链。
- [x] `pnpm -C ui test`、`pnpm -C ui exec tsc -b --noEmit`、`node quality-gates/run.js`、`archkit inspect .` 全部通过。

## Implementation

- `ui/src/components/run-panel.tsx`：新增可选入参 `availability`（默认 `"available"`）、`credentialHint`、`onAvailabilityAction`。`chatAvailable` 控制输入区：不可用时用 `AgentAvailabilityNotice`（panel 档）取代 textarea + 发送按钮，并在同一时刻抑制 `RunErrorBlock`，避免「重试」与「去设置」两块互相矛盾；默认值保证既有直接调用（storybook / 测试）行为不变。
- `ui/src/components/resume-chat-panel.tsx`：新增 `GET /models/config` + `GET /agent/runtime` 两路查询，用 `agentAvailability` 派生七态（把 `lastTest` 一并传入，凭据被拒才能判成 `auth_failed`）；把 availability / credentialHint / onAvailabilityAction 透传给 `RunPanel`；历史会话的「继续对话」输入同样按 `chatAvailable` 拦截；动作经 `agentAvailabilityActionEffect` 分流（`settings` → `navigate("/settings")`，`retry` → 重查两路查询）。`credentialHint` 提为变量，只把上游已掩码尾号交给通知组件过滤。
- 测试：`ui/src/components/run-panel.test.tsx` 新增「RunPanel AI 可用性引导」6 条（四态渲染与放行 / 拦截、auth_failed 掩码尾号与完整 key / Authorization / Traceback 负向断言、不可用不叠加错误块、可用时错误块照常可见）；`ui/src/components/resume-chat-panel.test.tsx` 新增「对话区 AI 可用性引导接线」8 条（四态接线、`/settings` 归一、load_failed 重试、历史会话拦截、不可用不叠加、available 放行）；新增 `ui/src/components/resume-chat-panel.stories.test.tsx` 4 条，直接渲染四态 story。
- story：`ui/src/components/resume-chat-panel.stories.tsx` 用 `StoryProviders` + `MemoryRouter` 渲染真实 `ResumeChatPanel`，经 MSW 的 `GET /models/config` / `GET /agent/runtime` 契约驱动四态；`applyAvailability` 先 `worker.resetHandlers()`，避免历史会话 story 的 handler 覆盖串场。
- 原型：`ui/prototypes/index.html` 对话区区块补「引导与运行错误块不叠加」规则说明。
- i18n：复用既有 `agentOnboarding` 命名空间，无新增文案键；`resume` 命名空间未变。
