# 扩展隐私门禁：个人邮箱、内网 IP 与常见本机路径

## Background

d703c 先落地了「带用户名的家目录绝对路径」门禁（`quality-gates/gates/repo-private-paths.js`）。但公开仓库的隐私红线不止这一条：Homebrew 安装前缀这类本机工具链路径、gmail / 163 等个人邮箱域、内网网段地址同样会暴露本机与个人身份，而这几类**没有任何门禁**，只能靠人工扫。

## Scope

- 把 `repo-private-paths` 扩成 `repo-privacy`（`git mv`）：家目录绝对路径、Homebrew 前缀、个人邮箱域、内网 IP 四类。
- 新增行内豁免标记 `privacy-allow`，与仓库既有的 `i18n-allow` / `form-allow` 同一约定，用于「规则说明本身要引用这些模式」的行。
- 同步 `docs/design.md` 的门禁清单与 `.freak` 记录。

## Non-goals

- 不扫描未跟踪文件与仓库外文件。
- 不改写 Git 历史。
- 不检查裸用户名、公网 IP、公司域名邮箱（这些不构成本机/个人泄漏）。

## Acceptance Criteria

- [x] 造一个含 gmail 地址、`/Users/<用户名>/`、内网 IP 的跟踪文件时门禁变红并逐条指出文件:行号与做法。
- [x] 删掉该构造文件后 `archkit inspect .` 通过（基线常绿）。
- [x] 规则说明类引用（反引号包住的 `/Users/`、`"@gmail.com"`）与项目域名邮箱（`admin@resumate.dev`）不误报；需要引用模式的规则行用 `privacy-allow` 豁免。

## Implementation

- `git mv quality-gates/gates/repo-private-paths.js quality-gates/gates/repo-privacy.js`，把检测扩到五类，每条都带 `label`（命中了什么）与 `fix`（该怎么做）：
  1. macOS 家目录绝对路径（`/Users/<用户名>/`）
  2. Windows 家目录绝对路径（`C:\\Users\\<用户名>\\`）
  3. Homebrew 安装前缀
  4. 个人邮箱域（gmail / googlemail / 163 / 126 / qq / foxmail / outlook / hotmail / live / yahoo / icloud / me / protonmail / proton / sina / sohu / 139 / 189）
  5. 内网 IP（`10.x`、`172.16-31.x`、`192.168.x`）
- 行内豁免标记 `privacy-allow`：与仓库既有的 `i18n-allow` / `form-allow` 同一约定，规则说明行自带该标记即跳过。
- 扫描面保持「Git 跟踪的文本文件」：未跟踪文件不在公开面；跳过二进制与超过 2 MiB 的文件；跳过门禁自身避免正则字面量自命中。
- 项目域名邮箱（`admin@resumate.dev`）不在个人邮箱域列表内，继续放行。
- `docs/design.md` 的门禁清单改名并写明四类拦截范围与占位符写法；`.freak` 更新为「这几类已由门禁兜住，手工 grep 只是兜底」。
