# 历史会话列表按会话呈现：话题标题与时间分组

## Background

用户以 DeepSeek 侧栏的会话历史为参照指出：chatbot 的历史对话应一行呈现一个 **session**（一个 session 含若干 message / 若干轮），而不是逐轮消息。

现状（修正前）：`ui/src/components/session-history.tsx` 的 `SessionList` 数据源已经是「每会话一行」，但行内容不对——主文案是 `session.title?.trim() || "未命名对话 · {{time}}"`，而 `title` 是后端暂未返回的展示层字段，于是每行都退化成「未命名对话 + 时间」；次行还渲染会话 ID（`SessionMeta` 里的 `idLabel`），像调试信息；列表没有时间分组。

## Scope

- `ui/src/components/session-history.tsx` 的 `SessionList`：一行一个会话；行主文案优先 `title`，缺失时用「未命名对话」兜底；行内（含可访问名）不出现会话 ID；按最近活跃时间分组：今天 / 昨天 / 7 天内 / 30 天内 / 更早，空组不渲染；保留既有 加载 / 空 / 错误 / 选中 四态与既有令牌、类名。
- `ui/src/i18n/locales/{zh-CN,en}/sessionHistory.ts`：新增分组键，更新「标题来源」说明；两语言键结构逐键一致，en 无汉字。
- 同步 `ui/prototypes/index.html` 的历史块（`#screen-session-history` 与个人资料助手抽屉的历史列表）。
- 同步受影响的 story 与测试选择器。

## Non-goals

- 不实现后端 `title` 派生，只给出结论与建议（见 Implementation）；本轮不接线 `GET /sessions`。
- 不改 `SessionDetail` 的消息流与 compacted 区块，不接真实端点、不动路由。
- 不改 `profile-assistant.tsx` / `resume-chat-panel.tsx` 的运行时行为。

## Acceptance Criteria

- [ ] 列表一行一个会话；行主文案优先 `title`，缺失时用「未命名对话」兜底，绝不渲染 undefined。
- [ ] 列表行内不出现会话 ID，可访问名同样不含 ID。
- [ ] 按 今天 / 昨天 / 7 天内 / 30 天内 / 更早 分组；空组不渲染；分组标题走 i18n。
- [ ] 次行只保留「最近活跃 + 相对时间」与「N 条消息」（`messageCount` 存在时）。
- [ ] 既有 加载 / 空 / 错误 / 选中 四态保留，令牌与类名不变。
- [ ] story 覆盖 跨组多会话 / 仅一个会话 / 标题缺失 / 加载 / 空 / 错误 / 选中。
- [ ] `ui/prototypes/index.html` 历史块与组件一致。
- [ ] `pnpm -C ui exec tsc -b --noEmit`、`pnpm -C ui test`、`node quality-gates/run.js` 全绿。

## Implementation

- 分组口径按**最近活跃时间**的日历日差（本地时区）：今天 = 0 天；昨天 = 1 天；7 天内 = 2–7 天；30 天内 = 8–30 天；更早 = > 30 天。无效时间归入「更早」，不丢行。
- 行内标题：`session.title?.trim() || t("sessionHistory.untitled")`；次行 `最近活跃 {{time}}` +（可选）`{{n}} 条消息`。
- **标题来源结论（后端要提供什么）**：建议后端在 `GET /sessions` 的响应项上返回派生字段 `title`，取值口径为「该会话**首条 role=user 的消息**正文去除首尾空白后截取前 N 个字符（建议 24 个字符，超出加省略号）」。实现上应为**单条相关子查询**（如 `ORDER BY seq ASC LIMIT 1` 的 lateral / 标量子查询），随会话列表一次查出，避免前端对每个会话再拉一次消息造成 N+1。为此后端需要保存或可反查「会话的首条用户消息」，当前 `agent_sessions` 只有 `id/owner_id/created_at/updated_at/last_active_at`，因此该字段落在 `agent_session_messages` 侧。
- 后端未提供前，前端继续用展示层可选入参 `title`，缺失即兜底。
