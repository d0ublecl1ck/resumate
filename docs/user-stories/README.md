# 用户故事索引

本目录将 Resumate 的产品需求整理为待实现的用户故事与公共行为契约。它描述目标行为，不表示业务接口或页面已经完成；现有架构见[设计蓝图](../design.md)。

## 阅读入口

| 文件 | 用途 |
| --- | --- |
| [jobseeker.md](jobseeker.md) | 求职者的简历、JD 管理与微调、Profile、授权、版本、设置及面试流程 |
| [admin.md](admin.md) | 模板管理员的创建、校验、发布、下架和维护流程 |
| [agent.md](agent.md) | 外部 Agent 使用者与集成者的 API、MCP、SDK 和事件接入 |
| [contracts.md](contracts.md) | 各故事共用的授权、版本、并发、安全与工程约束 |
| [coverage.md](coverage.md) | 产品主题覆盖、原有故事映射和需求澄清记录 |

## 角色

| 角色 | 用户目标 |
| --- | --- |
| 求职者 | 维护完整职业事实，创建并投递岗位简历，练习面试 |
| 模板管理员 | 提供可用模板并保持已使用模板稳定 |
| 外部 Agent 使用者 | 使用已有 Agent、个人记忆和资料操作简历 |
| 集成开发者 | 将公共能力接入 MCP 客户端、脚本或工作流 |

内置 Agent、面试官 Agent 和系统是实现参与者，其算法与协议约束不作为独立用户角色。原 US-9.3、US-11.2、US-11.4 已转为 ER-9.3、ER-11.2、ER-11.4，见公共契约。

## 已确定的统一行为

| 主题 | 决定 |
| --- | --- |
| 创建授权 | approval 中所有 Agent 创建均展示摘要并再次确认；直接创建（完全新开 / 从现有简历复制）以提交动作为确认 |
| Full Access | 普通写入免逐次确认；删除、回滚、覆盖导出、Profile 选材创建、显式同步及事实晋升保留确认 |
| 失败与取消 | 停止后续写入，权限有效时保留有效修改并 finalize；未批准提案不计入；冲突或授权撤销时冻结草稿待处理 |
| 对话确认 | 绑定待办的确认/拒绝属于原轮次的控制事件；新的独立任务消息才开启下一轮 |
| 正式版本 | apply 更新 Working Copy；finalize/flush 才提交正式版本；无变化不创建空版本 |
| 手动保存 | 默认最后一次输入后静默 30 秒提交；显式保存、切换、离开、导出触发 flush；关闭自动保存仅暂停静默提交 |
| 导出 | 先结算手动缓冲再固定版本；导出本身不修改源内容、不新增版本 |
| 迟到写入 | 已关闭 turn 一律拒绝，不转成隐式新任务 |
| 模式切换 | 会话覆盖 Agent，Agent 覆盖账户默认；Run 启动时固定，后续设置变更不改写当前 Run |
| JD 软绑定 | 一个 JD 可绑定 0 或 1 份简历，可换绑/解绑；微调可改选其他简历，绑定不随改选自动改变，删除 JD 不删除简历 |

详细约束以 [contracts.md](contracts.md) 为准。尚未给定的恢复期限、上传限制、支持语言、渲染指标等集中列在 C-11；它们是相关场景的验收前置条件，不应猜测为已确定数值。

## 使用与验收

1. 根据用户目标选择故事，读取其引用的公共契约和前置参数。
2. 为每个 Scenario 建立自动测试或可复现人工验收记录；固定输入、触发动作和预期结果。
3. 验证成功路径，同时覆盖该故事给出的拒绝、冲突、失败及恢复路径。
4. 原有 ID 不复用于无关能力；拆分后的对应关系维护在 coverage.md。

文档自检：在根目录执行 `git diff --check` 检查格式差异；执行 `archkit inspect .` 检查项目门禁。两者均不等价于业务场景已经通过。

## 暂不包含

- 复杂多 Agent 编排。
- 自动投递与招聘网站账号操作。
- Git 仓库作为简历存储。
- 企业多租户复杂权限。
- 实时文生视频数字人；数字人/DDS 为后续可选表现层，本期不设必加验收。
