# 用户故事：求职者

P0 为 MVP，P1 为增强，EXT 为比赛扩展。以下均为待实现的需求；共同验收依据为[公共契约](contracts.md)。每个场景只有一个触发动作；同一用户目标的成功、失败和边界场景保留在同一故事中。

## Epic 1：简历管理

### US-1.1 对话创建简历【P0】
> 入口后置：SCR-101 已收敛为「从现有简历复制 / 完全新开」，对话创建入口待 Profile 选材生成落地后重新定义（见 SCR-101、Q-01）。

作为首次制作岗位简历的求职者，我希望通过对话创建草稿并逐步补齐资料，以便无需先掌握编辑器就能开始准备投递。
```gherkin
Scenario: 授权后创建草稿
Given 我使用授权模式且尚无目标岗位简历
When 我说“创建一份后端工程师简历”
Then Agent 展示待确认的岗位、标题、拟带入的基本信息与来源，暂不创建资源
Scenario: 对话确认创建
Given 创建摘要已展示且我的 Profile 存有基本信息
When 我在对话中回复“确认创建”并明确对应待办
Then 系统在原轮次消费该确认，只创建一份带已确认基本信息的草稿，绑定为当前简历并提示待补资料
Scenario: 对话补齐经历
Given 当前草稿缺少项目经历
When 我描述真实项目经历
Then Agent 展示对应内容 Diff 供我确认，并将候选内容标为草稿预览
```

### US-1.2 找到目标简历【P0】
作为同时准备多个岗位的求职者，我希望搜索和排序简历，以便快速打开需要继续编辑的版本。
```gherkin
Scenario: 搜索和排序
Given 我有不同标题、标签和更新时间的多份简历
When 我按标题关键词搜索并选择最近编辑排序
Then 列表仅显示匹配的活跃简历，按更新时间降序排列
Scenario: 无匹配结果
Given 当前没有匹配搜索条件的简历
When 我执行搜索
Then 页面显示空结果及清除筛选入口，保留搜索条件
```

### US-1.3 复制简历创建岗位分支【P0】
作为投递不同岗位的求职者，我希望复制现有简历，以便定制新版本时保留原稿。
```gherkin
Scenario: 复制为独立草稿
Given 原简历已有内容、模板选择和事实来源
When 我在列表确认复制
Then 新草稿保留所选内容、模板和来源，并拥有独立身份与后续版本历史
Scenario: 编辑副本
Given 原稿与副本均存在
When 我保存副本的一处修改
Then 仅副本产生内容变更，原稿内容和历史保持不变
```

### US-1.4 对话切换当前简历【P0】
作为拥有多份简历的求职者，我希望在对话中明确引用和切换目标，以便修改准确落在指定简历上。
```gherkin
Scenario: 切换明确目标
Given 当前目标为 A，上一轮已结算，我拥有简历 B
When 我说“切换到 B”
Then 工作台和新轮次均绑定 B，后续工具不再默认修改 A
Scenario: 引用存在歧义
Given 有两份同名简历
When 我仅用该名称要求切换
Then Agent 展示候选供我选择，确认目标前不执行写操作
```

### US-1.5 手动结构化编辑【P0】
作为需要精调文案的求职者，我希望直接修改字段和章节顺序，以便准确表达自己的经历。
```gherkin
Scenario: 修改字段
Given 我正在编辑一份简历
When 我修改某条项目经历

Scenario: 调整章节
Given 简历包含教育、项目和自定义章节
When 我移动项目章节到教育之前
Then 草稿按新顺序显示，章节和条目身份及其事实来源保持不变
Scenario: 输入不满足字段约束
Given 某字段存在已公开的格式约束
When 我输入违反该约束的内容
Then 编辑器定位具体错误，保留可修正输入并阻止无效内容提交
```

### US-1.6 首页问候【P1】
作为返回继续编辑的求职者，我希望首页使用我的昵称和当地时段问候，以便识别当前账户和工作环境。
```gherkin

Scenario: 没有昵称
Given 我尚未设置昵称
When 我打开首页
Then 页面使用当前语言的通用问候，不显示空值或占位变量
```

### US-1.7 重命名简历【P0】


### US-1.8 归档与重新启用简历【P0】
作为阶段性结束投递的求职者，我希望将旧简历归档，以便保持活跃列表简洁并可再次使用旧稿。

```gherkin
Scenario: 重新启用

```

### US-1.9 删除与恢复简历【P0】
作为清理无用草稿的求职者，我希望删除后仍有明确的恢复机会，以便避免误删损失。
```gherkin
Scenario: 确认软删除
Given 我拥有一份简历且恢复窗口 D-01 已冻结
When 我确认删除该简历
Then 简历进入已删除状态，界面展示恢复截止时间，正常列表不再显示它
Scenario: 窗口内恢复
Given 简历已删除且尚在恢复窗口内
When 我请求恢复
Then 原简历内容、模板关联和版本历史恢复可用
Scenario: 窗口结束
Given 当前时间已达到恢复截止时刻
When 我请求恢复
Then 系统拒绝恢复并说明期限已过，不创建替代空简历
```

### US-1.10 用标签筛选简历【P0】
作为投递多个方向的求职者，我希望为简历添加标签并组合筛选，以便整理岗位和投递批次。
```gherkin
Scenario: 按标签筛选
Given 我为若干简历设置了“后端”标签
When 我选择“后端”标签及最近编辑时间范围
Then 列表仅显示同时满足标签和时间范围的简历
```

### US-1.11 手动新建简历【P0】
作为已准备好资料的求职者，我希望先把简历建出来、进编辑器再改，以便不被创建表单挡住。
```gherkin
Scenario: 完全新开
Given 有至少一个已发布模板
When 我选择「完全新开」并提交
Then 系统用默认标题与该模板创建一份空文档草稿，并打开编辑器
Scenario: 从现有简历复制
Given 我有至少一份活跃简历
When 我选择「从现有简历复制」并点「创建」
Then 系统不产生任何资源，先打开简历选择层，用网格卡片列出我的活跃简历
When 我在选择层选定一份并点「创建副本」
Then 系统把该简历文档复制成一份独立简历，标题追加「（副本）」，并打开副本编辑器
Scenario: 没有可复制的简历
Given 我没有活跃简历
When 我打开新建简历弹窗
Then 「从现有简历复制」不可选并说明原因，默认落到「完全新开」
Scenario: 没有已发布模板
Given 没有已发布模板
When 我打开新建简历弹窗
Then 「完全新开」不可提交并说明原因，复制链路仍可用
```

- 「创建后用 Profile 预填充」与对话创建入口后置：两者都依赖 Profile 选材生成，待其落地后再定义入口与确认语义（见 SCR-101、Q-01）。

## Epic 2：对话式编辑

### US-2.1 自然语言编辑简历【P0】
作为改进项目表述的求职者，我希望用自然语言说明修改目标，以便得到可审阅的具体改写。
```gherkin
Scenario: 授权模式下提出修改
Given 当前模式为 approval，简历与草稿基线已读取
When 我说“把项目经历第二条改得更量化”
Then Agent 为该稳定条目生成 Diff，尚未确认的修改不进入 Working Copy
Scenario: 缺少量化事实
Given 当前资料没有可支撑的业务指标
When 我要求量化项目成果
Then Agent 追问真实指标或给出不含虚构数字的候选文案
```

### US-2.2 跨简历语义比较【P1】
作为同时维护校招版和社招版的求职者，我希望比较两份简历的内容取舍，以便发现岗位表达差异。
```gherkin
Scenario: 比较两份简历
Given 我选择了有权读取的两份简历及其版本
When 我要求比较两份简历
Then Agent 按经历、技能和岗位相关性说明差异，并引用对应内容，不修改任一简历
```

### US-2.3 对话式撤销与回滚【P0】
作为尝试改写的求职者，我希望通过对话指定恢复目标，以便不必手动查找操作入口。
```gherkin
Scenario: 对话请求撤销
Given 当前简历存在可撤销提交
When 我说“撤销刚才修改”
Then Agent 展示将恢复的目标、反向 Diff 与待确认操作
Scenario: 时间范围有多个候选
Given 指定日期有多个历史版本
When 我说“回到那天的版本”
Then Agent 展示候选时间和摘要供我选择，不自行覆盖当前内容
```

### US-2.4 查看、取消与重试 Agent 执行【P0】
作为等待 Agent 完成编辑的求职者，我希望看到进度并能停止执行，以便控制等待和已产生的修改。
```gherkin
Scenario: 查看运行进度
Given 当前 Run 正在执行
When 我查看对话面板
Then 文本逐段显示，工具状态和待确认动作可区分，完成状态以服务端结果为准
Scenario: 取消执行
Given 本轮已有有效修改且仍有工具运行
When 我取消当前 Run
Then 系统停止后续写入并结算已完成修改，展示终止原因、最终 Diff 和撤销入口
Scenario: 失败重试
Given 上一 Run 失败且已有部分修改成功提交
When 我重试未完成任务
Then 系统从已保存状态开启新轮次，历史中不重复出现已成功提交的修改
```

### US-2.5 多对话恢复【P1】
作为分多次完善简历的求职者，我希望恢复历史对话，以便继续未完成的工作。
```gherkin
Scenario: 恢复历史会话
Given 历史会话关联的简历仍可访问
When 我打开该会话
Then 系统恢复消息与当前简历关联，并以服务端最新内容及待办状态继续工作
Scenario: 历史关联资源不可用
Given 历史简历已删除或访问权限已失效
When 我恢复会话
Then 消息历史保留，界面说明资源不可用并要求重新选择目标后再编辑
```

### US-2.6 批量引用和修改多份简历【P1】
作为批量更新共同信息的求职者，我希望一次指令作用于选定简历，以便减少重复编辑。
```gherkin
Scenario: 审阅批量变更
Given 我显式选择了 A 和 B，当前为授权模式
When 我要求更新两份简历的相同信息
Then 系统分别展示 A 和 B 的目标与 Diff，未选中的简历不受影响
Scenario: 部分提交冲突
Given A 的变更已批准且无冲突，B 的基线已过期
When 本轮结算
Then 系统分别报告 A 的成功版本和 B 的待处理冲突，不把批次显示为全部成功
```

## Epic 3：Diff 审阅

### US-3.1 看清修改内容与理由【P0】
作为审阅 AI 改写的求职者，我希望看到字段和行级对照，以便判断内容是否准确。
```gherkin
Scenario: 授权前审阅
Given 存在一份通过校验的待确认 Patch
When 我打开 Diff
Then 页面显示 before/after、新增和删除标识、上下文及语义摘要，颜色以外也能辨认变化类型
Scenario: Full Access 最终审阅
Given Full Access 已成功结束本轮普通内容编辑
When 我查看本轮结果
Then 页面展示聚合 Diff、理由、版本与撤销入口，明确内容已经提交
```

### US-3.2 逐项决定保留哪些修改【P0】
作为需要筛选 AI 建议的求职者，我希望接受、拒绝或调整每个修改项，以便只保留认可的内容。
```gherkin
Scenario: 部分接受
Given 待审 Patch 有相互独立的 A、B 两项
When 我接受 A 并拒绝 B
Then Working Copy 只包含 A，最终聚合 Diff 不含 B
Scenario: 编辑后接受
Given 我调整了待审建议的文字
When 我确认调整后的预览
Then 系统应用我实际审阅的负载，旧预览确认失效
Scenario: 全部接受的重复请求
Given 同一待审 Patch 已整体接受
When 我再次提交同一确认请求
Then 系统返回原处理结果，不重复应用 Patch 或生成版本
Scenario: 修改项相互依赖
Given 拒绝章节创建会使其内部新增条目失去目标
When 我只接受该条目
Then 系统指出依赖关系并要求调整选择，不提交结构无效的部分 Patch
```

## Epic 4：版本管理

### US-4.1 查看不可变版本历史【P0】
作为持续完善简历的求职者，我希望查看每次正式提交，以便追溯内容演变。
```gherkin
Scenario: 查看提交时间线

Scenario: 新提交不改写历史

When 新修改结算为 V2
Then V1 保持不变且 V2 记录其父版本，当前指针指向 V2
```

### US-4.2 对比任意两个版本【P0】

```gherkin
Scenario: 选择非相邻版本
Given 同一简历存在 V1、V2、V3
When 我选择 V1 与 V3 比较
Then 系统展示从 V1 到 V3 的字段、顺序和文本差异
Scenario: 同版比较
Given 我选择的两个版本相同
When 我执行比较
Then 系统显示无差异
```

### US-4.3 恢复、撤销与重做内容【P0】
作为需要恢复旧稿的求职者，我希望预览并确认恢复结果，以便放心尝试新的表达。
```gherkin
Scenario: 恢复历史版本
Given 当前为 V3，我已审阅恢复 V1 的反向 Diff
When 我确认恢复
Then 系统新建内容等于 V1 的恢复版本，保留 V1 至 V3 的原历史
Scenario: 撤销后重做

When 我确认 redo 预览
Then 系统以新版本恢复 undo 前的内容
Scenario: 新修改后不能重做旧分支

When 我请求 redo
Then 系统说明旧重做分支已失效，不覆盖新内容
```

### US-4.4 识别版本来源【P0】
作为核对编辑责任的求职者，我希望区分手动和 Agent 版本，以便找到对应操作与消息。
```gherkin

Scenario: 筛选手动版本

Then 列表只显示手动版本，并可查看其编辑会话和聚合时间窗口
```

## Epic 5：预览、导出与导入

### US-5.1 预览最终呈现【P0】
作为控制简历版式的求职者，我希望编辑时看到排版预览，以便发现溢出和内容缺漏。
```gherkin

When 我修改并提交一处有效草稿输入

Then 系统保留并标注旧预览，显示可重试错误，不把旧预览冒充最新内容
```

### US-5.2 导出可投递或可读文件【P0】
作为准备投递的求职者，我希望导出 PDF 或 Markdown，以便提交给招聘方或继续处理文本。
```gherkin
Scenario: 导出正式版本
Given 当前无待保存修改，模板与导出配置已确定
When 我选择 PDF 或 Markdown 导出
Then 系统提供对应版本的文件，不修改源内容或新增内容版本
Scenario: 导出前保存手动修改
Given 当前存在有效手动编辑缓冲
When 我请求导出
Then 系统先成功 flush 一个版本，再导出该版本，并显示其版本标识
Scenario: 保存或导出失败
Given 导出依赖的保存或渲染任务失败
When 我查看任务结果
Then 系统显示具体失败阶段和重试入口，不展示成功下载状态
```

```gherkin
Then 系统展示 B 的最终 Diff、版本与“绑定此简历”入口，不自动替换 JD 原绑定
```

### US-15.6 为 JD 绑定、换绑或解绑简历【P0】
作为管理岗位准备材料的求职者，我希望每个 JD 可关联一份简历，以便下次直接打开对应材料。
```gherkin
Scenario: 初次绑定
Given JD 当前未绑定，我拥有可访问的简历 A
When 我确认将 A 绑定到该 JD
Then JD 的唯一当前关联指向 A，不复制内容也不产生 ResumeVersion
Scenario: 替换当前绑定
Given JD 当前绑定 A，我已选择可访问的简历 B
When 我确认换绑为 B
Then JD 原子地改为仅绑定 B，A 与 B 的内容和版本历史均不改变
Scenario: 解除绑定
Given JD 当前绑定 A
When 我确认解绑
Then JD 变为未绑定，JD 正文与 A 均保留
Scenario: 换绑失败
Given JD 当前绑定 A，而目标 B 已删除或不属于我
When 我尝试换绑为 B
Then 系统拒绝操作并保留 A，不泄漏 B 的私人内容
Scenario: 多个 JD 复用同一简历
Given 简历 A 已被 JD1 绑定
When 我确认将 A 绑定到 JD2
Then JD1 与 JD2 均可引用 A，各自只有一个当前绑定，A 的内容与版本不变
```

### US-15.7 删除岗位记录而保留简历【P0】
作为清理不再考虑岗位的求职者，我希望删除 JD 时保留简历，以便以后仍能复用已准备的材料。
```gherkin
Scenario: 删除已绑定 JD
Given JD 绑定 A，删除摘要说明将解除关联并保留简历
When 我确认删除该 JD
Then JD 从管理列表移除，A 和历史版本中的 JD 快照保留，不发生级联删除
Scenario: 被绑定简历已删除
Given JD 仍保留，但其关联简历 A 已被删除
When 我打开该 JD
Then 页面标明关联简历不可用，提供换绑与解绑，不自动关联其他简历
```
