## 需求澄清

| 原需求存在的分歧 | 当前基线 |
| --- | --- |
| “创建按意图自动执行”与“授权模式所有写入确认” | approval 中创建一律再次确认；用户已确认此规则 |
| 取消可提交也可丢弃 | 保留已完成有效修改并 finalize；用户已确认此规则；授权撤销时停止提交并冻结草稿，等待所有者重新审阅 |
| Full Access 删除/回滚是否确认 | 高影响操作保留确认；用户已确认此规则 |
| apply 每次生成版本与轮次聚合冲突 | apply 只更新 Working Copy，finalize/flush 原子产生正式版本 |
| 导出不改数据与导出前 flush | 保存是前置步骤，导出固定保存后的版本，本身不产生版本 |
| 迟到写入拒绝或转系统任务 | 一律拒绝，避免旧请求改变新轮次 |
| PAT/OpenAPI 同时出现在 P1 和后续 P0 开放生态范围 | 按 P0 开放生态完整要求交付；SDK 沿用既有 P0 |
| 跨简历操作在故事中混为 P0 | 复制为 P0；语义比较与批量修改按产品增强范围列为 P1 |
| JSON/Markdown 导入导出与 PDF/Markdown 抽取混用 | P0 完整 JSON 备份恢复；Markdown 可读输出；P1 文档解析抽取 |
| 自动保存设置与固定 30 秒策略 | 默认开启 30 秒静默提交；关闭仅暂停静默提交，主动 flush 仍有效 |
| “基本信息长期不变”包含年龄 | 统一称基本信息；按 Profile 当前保存值带出，不假定年龄永久不变 |
| JD 仅作为临时输入 | 增设独立 JD 管理、简历选择与岗位微调；每个 JD 可软绑定一份简历，按用户追加需求列 P0 |
| 一条消息一个轮次与对话确认冲突 | 新任务消息开启轮次；针对待办的确认/拒绝留在原轮消费 |
| 先选事实与后生成文案的确认混同 | 选材创建摘要和首版实际内容分别按负载审阅；相同已展示负载不重复确认 |
| Webhook 和能力发现未明确优先级 | 本次规划 Webhook 为 P1、能力发现为 P0；均有独立故事 |

## 需要持续核对的范围

- C-11 的 D-01～D-05 参数在关联功能开发前由对应负责人冻结；故事中显式引用，不以空泛的“体验良好”替代。
- C-12 的技术选型写入对应实现设计；不得把未选择的方案当作现有架构。
- P1 模板边界预览工具不替代 P0 发布时必要配置和基本渲染校验。
- EXT 四个必加模块包含双岗位各四类题库及其知识支撑；独立简历题库生成入口、笔试题和数字人表现层不替代该必加范围。
