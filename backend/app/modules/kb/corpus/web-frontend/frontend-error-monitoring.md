同步运行时错误用 window.onerror，未处理的 Promise 拒绝用 unhandledrejection，资源加载错误（img、script、link）不会冒泡到 window.onerror，需要在捕获阶段监听 error 事件并检查 event.target。React 用 Error Boundary 捕获渲染期错误，但要记住它抓不到事件回调、异步代码、SSR 和自身错误，需要全局监听兜底。框架层可在 app.config.errorHandler 或类似钩子统一接管。上报要带用户标识、页面路径、版本、设备、浏览器与堆栈。

## sourcemap 与还原

生产代码经过压缩混淆，堆栈没有可读性，必须上传 sourcemap 到监控平台做还原。sourcemap 不能对公网暴露，否则等于泄露源码，常用 hidden-source-map 或上传后删除。要保证 sourcemap 与发布版本严格对应，并把 version、buildId 一起上报，否则还原会错位。构建与上传要进 CI，避免人工遗漏。

## 白屏检测与止损

白屏是前端最严重的事故，用户看不到任何内容也点不动。检测手段包括：页面加载后定时检查根节点是否有可见子节点、关键内容元素是否挂载、路由是否卡死，配合截图或 DOM 采样上报。定位顺序是先用 sourcemap 还原报错、再查资源是否 404 或 chunk 加载失败、再看接口是否整体失败、最后看是否样式或布局把内容挡掉。止损手段：错误率高企时回滚版本或切到稳定版本、给懒加载失败提供重试与兜底页、关键接口失败展示可交互的降级内容而不是空白。

## 指标体系与告警

错误监控要区分错误量与错误率，按页面、版本、浏览器、用户分群下钻，做同类错误聚合与去重，避免一次循环报错刷爆看板。设置告警阈值并联动发布系统自动回滚。埋点与错误上报本身要采样并限流，不能因为上报把页面拖慢或把监控后端打挂。上线后对比新旧版本的错误率是发布流程的固定一环。
