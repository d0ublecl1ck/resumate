# 单库单表到分库分表的在线迁移

## 迁移阶段与双写

> 本文是 resumate 项目自建的种子知识语料（model-authored seed corpus），用于 A11 岗位题库的检索引用，非对任何外部规范、标准或出版物的摘抄。

不停机迁移拆成四个阶段：准备、存量搬迁、增量追平、灰度切流。准备阶段先确定分片数与分片键，把目标分片表建好（结构、索引、唯一键都要带上分片键），并在应用层打开双写开关：写请求同时写旧库和新的分片库，读请求暂时只读旧库。双写要放在同一个业务事务之外、用本地消息表或可靠事件保证两边最终都写成功，写失败要落补偿表由定时任务重试，不能因为新库写失败就回滚旧库写入，否则旧库回滚、新库已写会直接产生不一致。影子表方案则不改业务代码，由中间件或 CDC 工具把旧库 binlog 转换成对新分片表的写入，适合不能改代码的老系统，代价是额外一跳延迟与工具运维成本。

## 增量追平与一致性校验

存量迁移用分批查询加批量写入，按主键或分片键分页，每批几千行，限速避免打满源库 IO。存量阶段产生的增量由 binlog 订阅（canal、Debezium 或云 DTS）持续回放到新库，追平的标准是延迟稳定在秒级且持续一段时间不再累积。一致性校验分三层：行数校验比对每个分片的行数总和，checksum 校验按分片键分段做逐段比对，抽样校验随机取主键比对字段值。校验先全量后增量，发现差异要按主键定位是漏写、重复写还是字段错位，修复后重新校验，直到连续多轮零差异。校验任务要能暂停和重跑，避免校验本身把源库压垮。

## 灰度切流与回滚

读流量按用户维度灰度：把用户 ID 哈希取模，先放 1% 读新库，再 10%、50%、100%，每档观察错误率、延迟与不一致告警。读写都切到新库后，旧库保留双写一段时间作为回滚窗口。回滚动作分三档：读回滚只需把灰度开关调回旧库；写回滚要关闭双写开关并停掉增量回放，让旧库重新成为唯一写入源；数据已写进新库无法回退时，用反向补偿脚本把新库增量写回旧库。回滚必须在切流前演练过，并明确触发条件（不一致条数、错误率、延迟），不能等出事再临时决定。

## 切流期的连接与容量

分片后连接数按「分片数 × 实例数 × 每实例最大连接」放大：16 个分片、200 个实例、每实例 maximumPoolSize=20，最坏情况就是 16×200×20=64000 条连接，远超单实例 max_connections，会直接打死数据库。切流前要按数据库承载倒推每实例连接上限，用共享连接池或中间件代理收口，给连接池配心跳、获取超时与熔断，并压测验证切流瞬间不会出现连接建立风暴。只读流量可以下沉到从库或缓存，写流量必须收口到分片代理。
