# Sentinel 熔断降级与容灾

## 资源与规则模型

> 本文是 resumate 项目自建的种子知识语料（model-authored seed corpus），用于 A11 岗位题库的检索引用，非对任何外部规范、标准或出版物的摘抄。

Sentinel 把受保护的逻辑抽象为资源，规则分为流控、熔断降级、系统自适应保护、热点参数、授权等。流控可按 QPS 或并发线程数，流控模式有直接、关联（A 关联 B，B 忙时限流 A）、链路（只统计某入口进来的调用）；流控效果有快速失败、Warm Up 冷启动预热、匀速排队。热点参数限流能针对某个参数值（如特定商品 ID）单独设阈值。规则可存本地也可持久化到 Nacos、Apollo 等配置中心，启动时拉取、变更时推送，避免重启丢规则。

## 熔断器状态机

熔断降级策略有慢调用比例、异常比例、异常数。熔断器三态：closed 正常放行并统计；满足阈值条件时进入 open，期间所有请求快速失败；熔断时长结束后进入 half-open，放行少量探测请求，成功则闭合，失败则重新打开。阈值要设最小请求数，否则低流量下几个异常就误触发。慢调用比例要定义 RT 上限（例如超过 800ms 记为慢调用）再设比例阈值。恢复瞬间最容易把服务再次打挂，因为积压流量会一起涌入，解决手段是半开阶段限制探测数量、恢复后配合客户端重试退避和队列预热，而不是一次性完全放行。

## 降级开关与业务预案

降级要求能秒级生效：开关存放在配置中心，客户端本地缓存一份并在拉取失败时用兜底值，推送通道断了也能靠轮询兜底。开关本身要可灰度、可回滚、有审计记录，上线前压测开关切换路径，避免切开关时反而引发全量刷新。降级后的一致性要提前设计：例如积分不再实时入账，就写本地消息表或 MQ，等服务恢复后异步补账并对账；只把非核心功能降级，核心链路必须在任何情况下保持可用。

## 系统自适应保护与压测

系统规则从整体维度保护：按 Load1、CPU 使用率、平均 RT、并发线程数、入口 QPS 设阈值，超过就自动限流。阈值必须来自全链路压测的真实水位，例如单机 CPU 70% 时对应的 QPS，而不是照搬别家数字。限流、熔断、降级、隔离要作为一套组合预案演练，明确触发条件、执行动作、观察指标和回切条件。
